# 待决事项

**你拿不准、又需要人来拍板的事，写到这里，不要停下来等。**

R0 回来后统一处理。在他回复之前，能推进的部分照常推进。

---

## 文件命名

```
协作/待决/<paper_id>.md
```

例：`csp-s1-2020.md`、`csp-s1-2019b.md`

**一个文件一个写者**，不会冲突。追加写，不要删别人写的内容。

---

## 一条问题的格式

```markdown
## Q1 · 标签申请

- **类型**：标签申请
- **状态**：待决
- **位置**：第 34 题（`csp-s1-2020-034`）
- **背景**：这题考的是单调栈求柱状图最大矩形，现有 topic 词表覆盖不到。
- **我的处理**：暂挂 `topic:ds`（最接近），已按此交付。
- **需要你定**：是否新增 `topic:monotonic`？还是并入 `topic:ds`？
```

**必须写清「我的处理」**——这样 R0 不在时，工作照样能往下走；R0 回来只需确认或纠正。

---

## 类型

| 类型 | 什么时候用 |
|---|---|
| `标签申请` | 需要 `topic:` 词表里没有的标签 |
| `规范问题` | SPEC 有歧义、有缺失、自相矛盾 |
| `存疑项` | 原件看不清、拿不准写了什么 |
| `源文件问题` | PDF 缺页、串页、损坏、广告层 |
| `工具问题` | 脚本报错、行为不符合手册描述 |
| `阻塞` | 完全无法推进，已停止 |

---

## 严重程度

在标题后标注，R0 按这个排序处理：

| 标记 | 含义 | 对工作的影响 |
|---|---|---|
| 🔴 阻塞 | 无法继续 | 已停止，等你 |
| 🟡 影响正确性 | 能继续，但结论可能错 | 已按最合理方案交付，**需要复核** |
| 🟢 待确认 | 不影响交付 | 已自行决定，知会一声 |

---

## 铁律

1. **不要停下来等回复。** 能合理决定的就决定，写清楚「我的处理」，继续干。
2. **不要绕过。** 遇到校验失败、写不进去、看不懂报错，如实记下来，不要注释掉检查、不要「先交付后修」。
3. **不要改共享文件。** 想改 SPEC / TAGS / tools，写进这里，由 R0 改。
4. **已经自行决定的事也要写。** R0 需要知道你在哪里做了判断。

---

## R0 的处理流程（供参考）

1. 读所有 `协作/待决/*.md`
2. 按 🔴 → 🟡 → 🟢 排序
3. 能改规范的改规范，能加标签的加标签（跑 `gen_tags.py`）
4. 把结论写回对应文件的「R0 回复」段
5. 需要返工的，写进 `协作/看板.md` 并重新派工
