## Q3 · 题解区由 `paintCard()` 渲染，不是 `qCard()`

- **类型**：规范问题
- **状态**：待决
- **严重度**：🟡 影响正确性（已按最合理方案实现并测试通过，请复核这个落点）
- **背景**：需求 §5.4 第 2 点原文是「**`qCard()`**：渲染题解区，默认折叠，带一个
  「题解」按钮点击展开。`qCard` 是列表与浮层共用的渲染器，改一处两边都生效」。
  但第 3 点又要求「考试模式在 `submitExam()` 之前整个题解区**不渲染**，提交后正常显示」。
- **我的处理**：把「题解节点的增删」放进 **`paintCard()`**，`qCard()` 只留一行注释说明。
  理由：切模式（`setQuizMode`）、交卷（`submitExam`）、重做（`resetQuiz`）走的都是
  `refreshQuiz() → paintCard()` 的重绘链路；若节点由 `qCard()` 一次性生成，
  交卷瞬间没有任何路径能把它补回来（`refreshQuiz` 只重画选项与结论）。
  这正是需求第 3 点自己要求的「提交后正常显示」所必需的。
  列表与浮层两边同样生效（两处都在 `qCard` 之后紧接 `indexQuizDom + refreshQuiz`）。
  同时 `indexQuizDom()` 会认领已存在的题解元素，避免浮层开合后插出两个。
  `bun tools/test_viewer.js` + `test_page.py` 的 16 项题解断言（含
  「提交前 0 条 / 提交后 42 条 / 重做后回到 0 条」）全过。
- **需要你定**：认可这个落点吗？如果你更希望严格照 §5.4 原文写在 `qCard()` 里，
  那就得让 `submitExam()` 额外触发一次整表重绘——那是更大的改动，我没做。

## Q4 · `validate.py` 里另写了一份 `question_bodies()`，没有 import 同步工具

- **类型**：工具问题
- **状态**：待决
- **严重度**：🟢 待确认
- **背景**：判定「题解块属于哪道题的正文」需要和 `tag_questions.py` 完全相同的
  正文区间算法（注释结束 → 下一个标题行或下一个注释）。最省事的写法是
  `from tag_questions import question_bodies`（`validate.py` 已经这样 import 过
  `gen_tags`）。但那会让**校验器的区间定义**依赖**被校验工具**的实现：
  同步工具若把区间算错，两边会一起错、校验器发现不了。
- **我的处理**：在 `validate.py` 里独立写了一份 ~20 行的 `question_bodies`，
  并在注释里写明「另写一份而不 import：校验器要能独立发现同步工具的区间算错」。
  两处都加了交叉引用注释。
- **需要你定**：接受这份刻意的重复吗？（代价是将来改正文边界规则要改两处。）
