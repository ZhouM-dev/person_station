## 三、格式（定案，照抄）

题解块写在**题目正文的最末尾**（选项之后），与选项之间空一行：

```markdown
##### 第 33 题

<!-- qid: csp-s1-2022-033 | type: single_choice | score: 3 | answer: B | tags: ... -->

若 `tlen=10`，输出为 2，则 `slen` 最小为（ ）。

- A. 1
- B. 10
- C. 0
- D. 12

> **题解**
> 答案：B
```

有存疑的题目，多一行 `解释：`：

```markdown
> **题解**
> 答案：B
> 解释：官方答案表给 D，但按卷面程序实编译运行……（说明为什么存疑）
```

### 3.1 逐字规格

| 项 | 规格 |
|---|---|
| 首行 | `> **题解**` —— `> ` 一个半角空格，`题解` 两字，两侧各两个星号，**行尾无空格** |
| 第二行 | `> 答案：<值>` —— 冒号用**全角 `：`** |
| 第三行起 | `> 解释：<正文>`，**可选**，仅存疑题写 |
| 前缀 | 每一行都以 `> `（半角 `>` + 一个半角空格）开头 |
| 位置 | 题目正文**最后**的内容，其后到下一个标题/注释之间只能有空行 |
| 前置空行 | 与上文之间**恰好一个空行** |
| 多行解释 | 允许换行，**续行也以 `> ` 开头**，但**不重复** `解释：` 前缀 |

### 3.2 答案的写法（★ 注意判断题）

| `type` | `meta.answer` | 题解里写 |
|---|---|---|
| `single_choice` | `A` / `B` / `C` / `D` | `答案：A` （原样） |
| `true_false` | `T` | `答案：√` |
| `true_false` | `F` | `答案：×` |

**判断题刻意用 `√`/`×` 而不是 `T`/`F`**：这是卷面答案卡的表达，学员一眼就懂；
机器读的是题块注释里的 `answer: T/F`，两者由校验器强制对应（映射表 `T→√`、`F→×`）。

### 3.3 什么题**不写**题解

**`meta.answer` 为 `null` 的题，整个题解块不要写。** 当前有 86 道：

- `csp-s1-2020` 全部 43 题（原卷无答案源）
- `csp-s1-2025` 全部 43 题（原卷无答案源）

**其余 214 题全部要写**：2019b 43 + 2021 43 + 2022 43 + 2023 43 + 2024 42 = **214**。

## 五、工具改造

### 5.1 `tools/tag_questions.py`（改）

现在它只同步题块注释。扩展为**同时同步题解块**——它的 docstring 本来就写着
「同步题块注释：把 meta.json 里的字段写回 paper.md」，加题解是同一件事的延伸。

**渲染函数**：

```python
TF_MARK = {"T": "√", "F": "×"}

def render_solution(qtype: str, answer, note) -> str:
    """题解块。无答案返回空串（该题不写题解）。"""
    if not answer:
        return ""
    val = TF_MARK.get(answer, answer) if qtype == "true_false" else answer
    lines = ["> **题解**", f"> 答案：{val}"]
    if note:
        body = note.split("\n")
        lines.append(f"> 解释：{body[0]}")
        lines.extend(f"> {ln}" for ln in body[1:])
    return "\n".join(lines)
```

**插入/更新算法**（照此实现，不要自由发挥）：

1. `question_bodies()` 已经返回每个题块的 `(qid, 正文, 注释位置)`，正文范围是
   「注释结束 → 下一个标题行或下一个注释」。
2. 在这个范围**末尾**往前扫：跳过空行，若遇到连续的 `>` 行且其中含 `> **题解**`，
   这一段就是旧的题解块 → **整块替换**。
3. 没找到 → 在范围末尾**追加**：先去掉尾部空行，写一个空行，再写题解块，再留一个空行。
4. 期望值与实际值不一致才计入 `changed`（与现有 `meta_differs` / `text_differs` 同样的双比对思路）。
5. `--check` 模式下不写入，发现不一致就报错返回 1。

> ⚠️ **`tag_questions.py` 的替换是从后往前做的**（避免位置偏移），
> 追加题解会改变文本长度，**务必确认这套「从后往前」在插入新内容时依然成立**，
> 或者改成先收集全部编辑再一次性重建。这里最容易出 bug，**写完必须用真实数据验证**。

### 6.1 `csp-s1-2024-030`（`answer` 现为 `C`）

```
`solve()` 里每次合并都写成 `h[i] = h[2*i] + h[i] + h[2*i+1]`，也就是把「左子树的串 + 结点本身 + 右子树的串」首尾相接，这正是二叉树中序遍历的定义；`h[1]` 最终得到的就是整棵树的中序 01 串。注意外层循环 `for (int i = n; i; --i)` 让 `i` 从大到小只是为了自底向上计算、保证算 `i` 时两个儿子已经算好，它描述的是计算的先后，不是拼出来的串的顺序——按下标递减算恰恰是 BFS 序的逆序，所以 A 也不成立。官方答案表此处给 A，与卷面代码不符，已按代码更正为 C。
```

### 6.2 `csp-s1-2024-031`（`answer` 现为 `A`）

```
`n = 10` 时按堆式下标建树，中序遍历得到下标序列 `8,4,9,2,10,5,1,6,3,7`，把每个下标代进素数表 `p[]`（是素数记 1）得 01 串 `0001010011`，其二进制值就是 83，所以输出的第一行是 83。因为 `K1 = 0` 且 `p1[k] = 2^k`，哈希 `h1` 恰好等于这个 01 串的二进制值，并非巧合。选项 C 的 54 是后序序列 `0000110110` 的值，B/D 的 424 是按下标 1..10 顺序的值，都是干扰项。官方答案表此处给 C，与卷面代码实跑结果不符，已按代码更正为 A。
```

## 七、两个必须遵守的边界

### 7.1 「题解」不是 `tags:` 词表里的标签

用户口语里叫「题解标签」，但它**不是** `TAGS.md` 里的 `feat:` / `topic:` 条目，
**不要**新增 `feat:solution` 之类的词，也不要往题块注释的 `tags:` 里加东西。
它是题块内部的**一个区块**。

> 若日后确需按「有无题解」筛题：214/300 都有，区分度太低，不值得建标签。

### 7.2 题解块内**不得**用围栏代码块

解释要展示程序输出时，用行内代码（`` `83` ``）或直接写字，**不要**写
```` ``` ````。原因：`validate.py` 会扫描 ```` ```cpp ```` 代码块做行号连续性检查，
题解里出现围栏会干扰它；而且带 `> ` 前缀的围栏在解析器里也不好处理。

### 7.3 `answers.md` 保持不用

`SPEC.md` §1 的目录结构里列了可选的 `answers.md`（答案与解析）。
题解现在落在 `paper.md`，**`answers.md` 继续保持「不使用」**——
在 SPEC §1 的注释里补一句说明，避免后人以为该往那里写。

## 附二、「有争议的题」判定口径（★ 执行者按此判断，不要自行放宽或收窄）

有答案的 514 题里，**绝大多数只写 `答案：`**（§6.5 原话：没有问题的题目只写答案）。
只有符合下面**任一**条件的题才写 `解释：`：

**必写（三类）**

1. **答案与某个来源冲突**：官方答案表或第三方来源给的值与本库实跑/推演结果不同，
   本库取了其中一个。要写清「对方给什么、本库取什么、依据是什么」。
2. **题面与答案不自洽**：按印出来的题面推不出所给答案，或题面数据自相矛盾
   （如印错关键数字、原卷印刷瑕疵导致选项与代码不匹配），影响学员能不能答对。
3. **答案不唯一或答案源可靠性存疑**：多个选项行为等价（都算对）；或答案源的卷别
   /官方性无法确认，本库是按内容映射得出的。

**不写（三类）**

4. 纯排版归一化：中西文空格、引号转反引号、行号前导零宽度、标题层级、
   引用块句末句号 —— 这些是 SPEC 规定的处理，不是争议。
5. 原卷别字、漏印、错别字，**不影响作答判分**的（如漏印行号、把「到」印成「倒」）。
6. 口径分歧但答案本身唯一且无冲突的。

> **拿不准就写。** 写多了只是多一行说明；漏写会让学员拿着一个矛盾答案无处求解。
> 但**不要**为了「统一好看」给所有题都加解释 —— 那违背原话。

## 附三、`answer_note` 的写法要求

## 三、组级「程序说明」

- 属于**大题组**（`阅读程序(1)` 这类），不属于任何小题，所以不在题解块里。
- 存储：`meta.json` **顶层数组** `groups[]`，每项
  `{ "name": "阅读程序(1)", "section": "part2", "program_note": "……" }`；
  `name` 必须与 `questions[].group` **逐字一致**。
- 落点：`paper.md` 该组的 **material 区**——`<!-- group: -->` 之后、代码块之后、
  **本组第一个 `####` / `#####` 之前**（受 §3.0 悬空内容规则约束，插错位置会被并进上一题）。
- 长度 60~500 字，学员视角；写「这段代码在求解什么、输入输出是什么、关键做法是什么、
  理解本组题要抓住的一两个要点」，不是逐行注释。
- **与答案无关**：没有答案源的卷（如 `csp-s1-2020`）照样能写、也该写。
