### 复核方式

本卷正文实际分辨率只有 1080 px 宽（见第一节），因此**没有**用


关键行（代码、选项、`①`–`⑤`）都做了**逐行隔离回看**：把每一行单独裁成条带、
之间加红色分隔线再纵向拼接，**消除行对齐误差**——正是这个办法抓到了下面那处错误。

### ⚠️ 复核中抓到并已修正的一处错误（记录在案）

**位置**：第三节完善程序(2) 的代码头部。

- **初读**（200dpi 页面图）记为 **5 个 `#include`**（algorithm / cstddef / **cstdio** /
  iostream / vector），全块 **87 行**。
- **复核**（1080 px 内容图 + 逐行隔离回看）确认原卷只有 **4 个 `#include`**：
  `algorithm` / `cstddef` / `iostream` / `vector`——**没有 `<cstdio>`**。
- **旁证**：该程序通篇只用 `cin` / `cout` / `endl`，**不用 `scanf` / `printf`**，
  确实不需要 `<cstdio>`；反之上游那一行若真是 5 个 include，全块会变成 87 行，
  与「第 16 页到第 43 行、第 17 页从第 44 行接续、末行为第 86 行」的原卷事实矛盾。
- **处理**：删去多写的那一行并整体重排行号，全块现为 **1..86**，与原件逐行对齐。
  `①`–`⑤` 的落点也随之校正为第 **33 / 52 / 58 / 70 / 76** 行
  （与 200dpi 页面图复核的结果完全一致）。

> 这正是手册 10 §6「代码行号错位」的坑：**行号错了题目就废了**。
> 虽然本题组没有「第 N 行」引用（第 39–43 题都不引用行号），不会直接判错，
> 但行号保真是 SPEC §3.6 的硬要求，已修正。
