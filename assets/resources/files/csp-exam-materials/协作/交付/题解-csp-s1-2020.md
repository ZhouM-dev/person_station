## 二、5 段组级程序说明（全文）

### 组 1 · 阅读程序(1)（`part2`，`paper.md` 第 218 行）

> **程序说明**
> 这段程序先读入 n 和 n 个整数 `d[0]`…`d[n-1]`，再枚举所有满足 `d[i] < d[j]` 的下标对，把 `d[i] + d[j] - (d[i] & d[j])` 的最大值输出；如果一个这样的下标对都没有（例如 n 为 1，或所有 d 都相同），就输出初值 `-1`。关键一步是把那个表达式看出来：由 a + b = (a & b) + (a | b) 可知它恰好等于 `d[i] | d[j]`，所以程序求的是「任取两个下标、按位或之后能得到的最大的数」，是「或」而不是「和」。理解这一组要抓住两点：一是内层判断用的是严格小于，两个相等的元素不会被配对，`ans` 可能一直停在 `-1`；二是数组只开到 `int d[1000]`，所以输入的 n 必须小于 1000，否则读入时就会越界。

（357 字）

### 组 2 · 阅读程序(2)（`part2`，`paper.md` 第 316 行）

> **程序说明**
> 这段程序求一组数里第 k 小的数：先读入 n、k 和 n 个整数 d，再用 `find(0, n - 1, k)` 输出答案。`find` 是随机化的快速选择（quickselect）——先用 `rand()` 在当前区间里随机挑一个位置，把它换到区间左端当枢轴，再用左右两个指针 `a`、`b` 从两端向中间扫，遇到左边不小于枢轴、右边小于枢轴的数就交换；一轮划分结束后就能确定这个枢轴在本区间内排第几，若正好是第 k 个就返回它，否则只在含第 k 小的那一半区间里继续递归。理解这一组要抓住两点：一是第 17 行的 `swap` 是划分中真正的交换动作，它的执行次数取决于输入的排列和随机枢轴，平均是 O(n)、最坏会退化成 O(n²)，这一组关于复杂度的选择题都围绕它展开；二是这里说的「平均」是对随机数取平均，同一个输入多跑几次结果可以不同。

（375 字）

### 组 3 · 阅读程序(3)（`part2`，`paper.md` 第 485 行）

> **程序说明**
> 这段程序在字符串上做最短步数搜索：读入两个字符串 `st0`、`st1` 和整数 m，输出把 `st0` 变成 `st1` 的最少操作次数；两者长度不同输出 `-1`，本来就相等输出 `0`，搜完仍无解也输出 `-1`。一次操作是把字符串的一段整体循环平移一位：`LtoR(s, L, R)` 把 `s[L]` 挪到 `R`、中间字符左移，`RtoL` 正好相反；两边各对下标 `0..m` 的前段和 `m..len-1` 的后段动手，方向互为逆操作，所以这是在同一张图上从两端同时搜。关键做法是双向 BFS：`s[0]`、`s[1]` 是两个手写的映射表（键是字符串、值是从各自起点走了几步），`q[0]`、`q[1]` 是两边各自的队列，外层循环用 `p ^= 1` 让两边轮流扩展；`check` 一旦发现新串已经在另一边的表里，就把两边的步数相加输出——这就是两边相遇的时刻。理解本组要记住：`check` 只把新串插入当前这一边的表，`Map::find` 找不到时返回 `-1`，`maxl` 只是容量上限，不参与算法逻辑。

（468 字）

### 组 4 · 完善程序(1)（`part3`，`paper.md` 第 629 行）

> **程序说明**
> 这段程序求分数背包的最大价值，并以分数形式输出：有 n 块蛋糕，第 i 块价值 w_i、体积 v_i，盒子容量为 B；每块蛋糕可以任意切开、按比例带走它的价值，要求装进盒子的总价值最大，输出时要约分（分母为 1 时只输出整数）。做法是贪心：每单位体积带来的价值是 w_i / v_i，所以先把蛋糕按性价比从大到小排序（第 33 至 38 行是冒泡排序，①处就是相邻两块比较性价比的条件），再从第一块起依次整块装进盒子；装到某一块放不下时，把它切开、只取刚好填满剩余体积的那一部分。理解本组要抓住几点：①处的比较不能直接写整数除法（会丢精度），要用等价的乘式；中间那个二分支在判断第 1 块（性价比最高的一块）能不能整个装进盒子，装得下就把它整块计入并继续循环，装不下就直接是切开填满的情形；切开填满那一步要交给 `print` 的是分子和分母两个数——分子是已装价值加上新切进来那部分的价值，分母是这一块的体积，`print` 内部用辗转相除约分后再输出；循环自然结束时说明所有蛋糕都装下了，也交给 `print` 输出总价值。

（464 字）

### 组 5 · 完善程序(2)（`part3`，`paper.md` 第 754 行）

> **程序说明**
> 这段程序求最优子序列：给出长度为 n 的序列 a（0 ≤ a_i < 2¹⁶），子序列的得分是它相邻两项异或值的 w 之和，其中 w(x) = x + popcnt(x)，即 x 加上它二进制中 1 的个数；空子序列得分为 0，求所有子序列中最大的得分。做法是动态规划加折半优化：因为 a_i 只有 16 位而 n 可达 40000，直接记「上一个是哪个数」太慢，于是把 16 位拆成高 8 位和低 8 位，用 `Max[x][y]` 记下「子序列下一个位置的高 8 位是 x、最后一个位置的低 8 位是 y」时的最大得分；每读入一个数 a，先用它的低 8 位与枚举出的过渡值 z 查表，得到以 a 结尾的最优值 v，再用 v 更新所有可能的高 8 位状态的 `Max` 表，每一步只要枚举 2⁸ 种状态。要抓住几点：`w(x)` 里 s 的初值就是 x，循环每轮让 x 少一个 1，所以循环次数等于 popcnt(x)；`to_max` 只做「更大就赋值」；`Max` 表初值 `-INF` 表示不可达；空子序列得分为 0，所以每个数都可以作为新子序列的开头，答案从 0 开始。

（490 字）

### 6.3 读代码时注意到的、**会影响阅读但不影响转写**的几处（原卷写法，非转写错误）

1. **阅读程序(3) 的 `maxl = 2000000000` 只是示意**：`item d[maxl]`（每个 item 带 `string`）
   与 `string q[maxl]` 在真实环境里绝无可能分配；这两个类是「手写哈希表 + 先进先出队列」的
   示意实现。学员若真去编译运行会立刻失败，读题时要当成伪代码看待。
2. **`Map::end()` 是 `static`，返回 `-1`**：第 60 行写的是
   `if (s[p ^ 1].find(st) == s[p].end())`——拿**另一个对象**的 `find` 结果去和**这个对象**的
   `end()` 比较。因为 `end()` 是静态的、两个对象都返回 `-1`，所以能正常工作；但这是读代码时
   最容易被误判成 bug 的一处，值得在讲这组题时点一句。
3. **完善程序(1) 的 `print(int w, int v)` 形参遮蔽了全局数组 `w[]`、`v[]`**；同一份代码里
   还自定义了 `void swap(int &x, int &y)`，与第 2 行 `using namespace std;` 引入的
   `std::swap` 并存（不限定名调用会选中自定义的那个）。两处同名都不影响结果，但读的时候
   容易看错「谁是谁」。
4. **阅读程序(2) 的 `rand()` 没有 `srand`**（种子固定），且第 9 行的 `x` 取值是 `[L, R]`
   ——题面第 22 题的主张是 `[L+1, R]`；这正是该小题的考点，不是笔误。
5. **阅读程序(1) 的 `int d[1000]` 与题面「`n` 不超过 10000」冲突**——这正是第 16 题
   （「$n$ 必须小于 1000」）的考点，不是转写错误。（阅读程序(2) 的 `int d[10000]` 与题面
   「不超过 10000」是自洽的。）
6. **完善程序(1) 末尾的行号 ` 58`、` 59` 没有代码**：核验报告已实测确认是卷面印出来的
   空行号（原卷代码区预留行），转写照录、我也按现状保留。删掉会让「第 N 行」引用整体错位。
7. **完善程序(1) 的 `print(⑤)` 分支只在「所有蛋糕都装进盒子」时到达**（循环自然结束），
   此时盒子里通常还剩空间；这和前面「装不下就切」的分支互补，读的时候别把两处搞混。
8. **完善程序(2) 的 `x = ②` 左侧是 `int`、`a` 是 `LL`**；`Max[MS + 4][MS + 4]` 用 260 而非 256
   开界。都没有异常，只是读表时要留意下标范围是 `0..MS`（即 `0..255`）。
