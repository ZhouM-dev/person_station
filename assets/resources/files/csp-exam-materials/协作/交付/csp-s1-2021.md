## 存疑项

1. **第 2 题选项 A 与 C 文字完全相同**（均为 `00111100₂`）。
   放大原 PDF 逐字确认：这是**原卷自身的印刷重复**，不是转写错误。已照录，未订正。
   答案 B（`01000000₂`）不受影响。

2. **第 28 题官方答案为 ×，但我未能自行复现该判定。** 🟡
   题干：「程序总是先输出一行一个整数，再输出一行一个字符串。」
   按代码推演：第 61 行 `init()` 后第 62 行 `cout << int(table[0])` 必输出一个整数
   （`table[0]` 未被 `base[i]` 覆盖，初值 `0xff`，转 `int` 得 −1），第 67 行必输出一个字符串。
   两种读法都指向「命题为真」，与官方答案 × 相反。
   已按**官方答案记 `F`**（不猜、不擅改）。**请 R2 实际编译运行复核**，若确认官方答案有误再上报 R0。

3. **第 14 题的 `n = \overline{abc}` 上划线未能还原。** 🟢
   页面内置公式转换器（`viewer.html` 的 `renderMath`）不支持 `\overline`，写 `$\overline{abc}$` 会
   退化成 `overlineabc`。已改写为 `$n=abc$`，语义（abc 为 n 的十进制三位数字）由同句
   「设一个三位数」兜住。详见「规范问题」第 2 条。

4. **答案件出处未获权威确认。** 🟢
   `2021-答案.pdf` 是带「福建」水印的扫描件，无官方标识。因其 p001–p016 与本卷试题逐字一致
   （故卷别相同、无选项重排），且答案表编号 1–43 与本卷连续编号天然对齐，`answer_source.kind`
   暂填 `official` 并在 `note` 中写明来历，请 R0 确认是否应改判 `mapped`。

## 规范问题

1. **零填充行号的写法未在 SPEC 中约定。** 🟢
   2021 原卷代码行号是**零填充**的：阅读程序/完善程序(1) 用 `01`–`69`，完善程序(2) 用 `001`–`121`。
   SPEC §3.6 只规定「行号右对齐占 3 列 + 2 空格」，未说明是否保留前导零。
   **我的处理**：保留原卷的前导零（` 01  #include <iostream>` / `001  #include <iostream>`）。
   两者都满足「宽度 = 3」的校验规则，且更贴合「行号必须与原卷一致」。
   （2019 卷原卷本身无前导零，故写成 `  1`，两卷风格不同但各自忠实于原卷。）
   建议 R0 在 SPEC §3.6 补一句明确规定，以免各年不一致。

2. **公式转换器不支持 `\overline`，与「照录原则」冲突。** 🟢
   第 14 题原卷为 `n = \overline{abc}`。SPEC §3.5 要求行内公式用 `$...$`，
   但 `viewer.html` 的 `renderMath` 符号表中没有 `overline`/`bar`，会退化为去掉反斜杠的原文。
   **我的处理**：写作 `$n=abc$`，未自造标记。建议 R0 二选一：给转换器加 `\overline` 支持，或在
   SPEC 中登记「上划线暂不还原」这一已知缺口（与手册 04 §四的「整段缩进的提示段落」同类）。

3. **`feat:lineref` 的正则漏掉顿号连接的多行号。** 🟢
   `tools/tag_questions.py` 的判定是 `第\s*\d+\s*行`。第 17 题原文作「第 26、27 行中的……」，
   数字后接顿号，正则不匹配，故**第 17 题未挂 `feat:lineref`**，而第 16、18 题挂了。
   三题实际都引用了行号，标记不一致。属工具行为，**未改 `tools/`**，按铁律上报。
   建议 R0 将正则放宽为 `第\s*\d+(\s*[、,，]\s*\d+)*\s*行`，并对全库重跑 `tag_questions.py`。
