## 三、5 段组级「程序说明」全文

### 组 1 · 阅读程序(1)（`part2`）· 286 字

这段程序读入一个整数 n，统计 1 到 n 之间有多少个三元组 (i, j, k) 满足 i < j < k 且两两互质（互质用递归写的辗转相除法判断，最大公约数等于 1 才算），最后输出这个三元组的个数。三重循环按 i < j < k 枚举全部组合，第 16 行的三个 `gcd` 条件要同时成立才会把答案加一。理解本组要抓住两点：一是「互质」必须两两都满足，只要有一对不互质整个三元组就不算，所以第 16 行删掉其中任何一个条件统计都会变松、答案都会变大；二是无论 n 多大，(1, 2, 3) 这三个数总是两两互质的，所以 n ≥ 3 时答案至少有 1、恒为正整数。

### 组 2 · 阅读程序(2)（`part2`）· 318 字

这段程序读入 n 与 k，再读入 n 个整数，先排序、再去重，然后用一个只前进不后退的指针 j 从左到右扫一遍：对每个 i，把 j 推到「a[i] - a[j + 1] ≤ k」为止，再令 ans[i] = ans[j] + 1，最后输出 ans[n]。它的含义是把这些数分成尽量少的连续段，使每段内最大值与最小值之差不超过 k——排序后每一段就是若干个连续取值，ans[i] 表示覆盖前 i 个数至少要几段。理解本组要抓住两点：一是 j 单调不回退，每个元素至多进出窗口一次，整个循环是线性的，既然 j ≤ i 恒成立，答案也就落在 1 到 n 之间；二是去重那一行删掉并不改变答案，重复元素只会让同一段里多几个相等的值，段数不会变。

### 组 3 · 阅读程序(3)（`part2`）· 355 字

这段程序读入 n 与两个长度为 n 的数组 a、b，用一个二维数组做动态规划求它们最长公共子序列的长度：f[i][j] 表示只看 a 的前 i 个与 b 的前 j 个时能匹配出的最长公共子序列长度，转移时先继承 f[i - 1][j] 与 f[i][j - 1]，再在 a[i] == b[j] 时用 f[i - 1][j - 1] + 1 更新，最后输出 f[n][n]。理解本组要抓住两点：一是第 18 行的「继承」不能少，它保证 f 沿行、沿列都不下降，才有 f[i][j] ≤ f[n][n]；二是答案与元素顺序有关——把两个数组各自排序后，公共子序列退化成「两个多重集合的公共部分」，只会变大或不变；而 a 恰好是 1 到 n 的升序排列时，公共子序列必须递增，问题就等价于求 b 的最长上升子序列。

### 组 4 · 完善程序(1)（`part3`）· 267 字

这段程序把行程长度编码（形如 `A12` 表示 12 个 A、`B` 表示 1 个 B）展开成原始字符串。它从左到右扫编码串：若当前字符后面紧跟着数字，就把这串数字读成整数（逐位乘 10 累加），再把这个字符重复输出那么多次；否则该字符只出现一次，直接接到结果末尾并让下标前进一格。输入是一行不含空白的压缩字符串，输出是解压后的字符串。理解本组要抓住两点：一是「字符 + 数字」里的数字可能有多位，必须按十进制逐位累加，不能只取最后一位，也不能把各位数字相加；二是无论走哪条分支下标都必须前进，否则会在同一个字符上反复处理、程序卡死。

### 组 5 · 完善程序(2)（`part3`）· 314 字

这段程序在「精明人严格占多数」的前提下找出一个必定是精明人的人。它维护一个候选者 candidate 和一个计数 count，从头扫一遍：count 归零时就改用当前这个人作候选、并把 count 置 1；否则让候选者与当前这个人互相判断一次，只要有一方说对方是糊涂人，就认定这两人里至少有一个糊涂人、把这一对一起消掉（count 减一），否则两人都算数（count 加一）。输入是人数 N，输出最后留下的候选者编号。理解本组的关键是这条「消去」不变量：每消掉一对，消掉的人里至少有一个糊涂人，而精明人本来就过半，所以剩下的候选人不可能被消成糊涂人；一旦 count 归零说明此前的候选已被抵消干净，必须重新以当前这个人为候选。
