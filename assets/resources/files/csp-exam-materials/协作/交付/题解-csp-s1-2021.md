## 三、5 段组级程序说明（全文）

### 阅读程序(1)（`part2`，402 字）

> **程序说明**
> 这段程序读入两个球的球心坐标与半径（依次是 a1 b1 c1 d1 和 a2 b2 c2 d2），输出这两个球公共部分的体积，结果固定打印 4 位小数。做法是先用平方和算出球心距的平方 t（避免开方带来的判断误差），再分三种情形：一个球完全含于另一个（t 不超过 (d2 − d1)²）时输出小球的体积 `cu(min(d1, d2)) * r * 4`；两球相离（t 不小于 (d1 + d2)²）时输出 0；部分相交时按两块球缺的体积公式相加。r 的取值是 `acos(0.5)`，也就是 π/3，正是球体积公式里的那个因子，不是 30 度角。理解本组要抓住两点：一是第 21 行的 t 是整数，第 26、27 行的除法里只要出现两个整数相除就会被截断，这一组三道「把某处改一下结果会不会变」的小题全都落在这上面；二是判断「内含」和「相离」用的都是平方，边界正好是相切，题给的相切输入值得亲手代一遍。

### 阅读程序(2)（`part2`，344 字）

> **程序说明**
> 这段程序读入 n 和 n 个整数，用两种写法求同一个量——最大子段和（允许一段都不取，所以答案不会小于 0）——并把结果各输出一行。`solve1` 是分治：每个区间返回「最大前缀和、最大子段和、最大后缀和、区间和」四元组，两个区间的四元组用重载的 `operator+` 拼出跨过中点的最优解，整棵递归树约 2n 个结点，复杂度 Θ(n)。`solve2` 同样分治，但每次还要从分界点向两侧各扫一遍求跨中点的最大和，代价与区间长度同阶，复杂度 Θ(n log n)。理解本组要抓住两点：一是两种写法的答案必然相同，可以拿随机数据对拍验证；二是第 31 行把区间从中间劈开后，两个子区间一定都非空，所以「h > m」这个空区间分支在递归内部永远不会被触发，这一组的判断题正是围绕这一点。

### 阅读程序(3)（`part2`，469 字）

> **程序说明**

### 完善程序(1)（`part3`，401 字）

> **程序说明**

### 完善程序(2)（`part3`，394 字）

> **程序说明**
> 这段程序解决区间最大值查询：读入 n 个数和 m 次询问，每次输出数组中第 l 到第 r 个数的最大值。做法分三步。先用单调栈建一棵笛卡尔树——父亲不小于儿子，弹栈得到的挂在左边、留在栈顶的挂在右边；再对树做 DFS 得到 Euler 序列，序列上两点之间最小值所在的位置就是这两点的最近公共祖先，于是原问题变成 Euler 序列上的 ±1 RMQ。最后用「把序列每 b 个分成一大块」的办法让每次询问近似 O(1)：大块之间用 ST 表；块内把相邻两点的上下坡压成一个差分模式 S，预处理出每种 S 下最小值第一次出现的位置 `Pos[S]`，查询时从 `Dif` 里截出对应的那几位即可。理解本组要抓住三点：笛卡尔树的左右孩子分别来自弹栈与栈顶；`min` 比的是 Euler 序列上的深度而不是结点的值；`Dif` 的位约定（1 表示深度下降）必须与重建折线、截取位段两处完全一致。

## 五、写了 `争议：` 的题（2 条）及理由

### 5.1 `csp-s1-2021-028`（答案 F）—— 有争议

**解释**（`answer_note`）：第 62 行 `cout << int(table[0]) << endl;` 是无条件执行的：`table` 先被 `0xff` 填满，而 `base[i]` 里的字符（大写字母、小写字母、数字、`+`、`/`）没有一个的 ASCII 码是 0，所以 `table[0]` 始终是 `0xff`，本平台 `char` 有符号，转成 `int` 就是 −1——第一行确实总是一个整数。但第二行未必是「一行」：`opt = 1` 时执行 `decode`，而 `decode` 还原出来的是任意字节序列，完全可能含换行符，这时第二行会裂成好几行。实跑：输入 `1 YQpi`，`YQpi` 解出的是 "a\nb"，程序输出三行（`-1`、`a`、`b`）；输入 `1 Cg==` 也会多输出空行。所以「总是……再输出一行一个字符串」不成立，本题判 ×。

**争议**（`dispute_note`）：按代码表面看很容易得出相反的结论：第 62 行与第 67 行各输出一行、都带 `endl`，像是「总是输出两行」，本题的正确答案却是 ×。本卷维持原卷的 ×，依据是实跑反例：按题面「一个整数和一个不含空白字符的字符串」给出的合法输入 `1 YQpi`，程序输出三行（`-1`、`a`、`b`）——`YQpi` 这四个字符里没有任何空白，完全符合题面假设，它解出的字节序列中却含换行符，第二行因此裂成了两行。判断「总是……」这类全称命题，只要有一个合法输入不满足就不成立。


### 5.2 `csp-s1-2021-037`（答案 C）—— 有争议

**解释**（`answer_note`）：第 30 至 41 行是「用本轮定标的 x 去更新其它数」，这些更新必须建立在已经确定最优值的数上，所以遍历时只处理 `Vis[i]` 为真的下标，即 ④ 填 `Vis[i]`，选 C。A 项 `F[i] < F[x]` 里 x 本来就是这些数中 F 最小的，条件几乎不可能成立，松弛基本不发生（实跑 29/30 崩溃）；D 项 `i <= x` 与「是否已定标」毫无关系，实跑 30/30 结果都不对；B 项 `F[i] <= r` 在小数据上也能得到同样的输出，但它表达的不是题面要求的「已经定标」，详见下方的争议。

**争议**（`dispute_note`）：本题原卷答案是 C，但选项 B（`F[i] <= r`）在「输出结果」这一维度上同样成立：把四个候选分别代进程序编译运行（其余空位固定为原卷答案），B 在 n = 1 到 30 上全部正确；进一步在 n = 1 到 200 全部、201 到 10000 随机抽 300 个再加上若干大值，共 512 个 n 上比对，B 的输出与 C 完全相同，0 例差异。原因是定标到第 r 轮时必有 F[x] ≥ r，已定标的数总会在较晚的那一轮被 `F[i] <= r` 命中，所以 B 相当于 C 的「延迟版」，既不会漏配也不会低估。本卷仍按原卷取 C，因为 ④ 的位置表达的语义是「该数已经定标」，只有 `Vis[i]` 是这个意思。

**判这两条的理由**（判据是「学员照卷面能不能推出所给答案、会不会产生错误理解」）：

- `csp-s1-2021-028`：**原卷给的 × 与代码表面看到的东西相反**。第 62 行与第 67 行各输出一行、
  都带 `endl`，照代码推演很容易选 √；要选对必须想到「`decode` 出来的字节里可以有换行符」。
  属于「题面（表面）与答案不自洽、学员会对自己算出来的 √ 起疑」那一类，**必须写**，
  且依据可复核（合法输入 `1 YQpi` 实跑输出三行）。
  v1 阶段这条的说明写在 `解释：` 里（v1.4 把解释与争议混在一栏），v2 按新规范拆成两栏。
- `csp-s1-2021-037`：考查「答案不唯一／多选项行为等价」。核验把 ④ 的四个候选逐个代进去编译运行，
  干扰项 B（`F[i] <= r`）在小数据上也能全对，进一步在 512 个 n 上与 C 输出完全相同、0 例差异，
  并在理论上证其等价（相当于 C 的「延迟超集」）。学员若选 B 需要一个说法，**写**。
  依据可复核（候选代入的实跑输出与 512 个 n 的比对，已写进争议正文）。
