# 06 · 答案处理

**这是最容易出错的一环。** 2019 就在这里踩过坑，代价是 43 题全部要重新映射。

---

## 一、头号陷阱：答案字母不能直接抄

**同一道题，不同卷别的选项顺序可能不同。**

CSP 分 A/B 卷，**题目相同、选项重排**。第三方答案表往往是另一卷的，
它的 `B` 对应的是**它的**选项 B，不是你的。

### 实例（2019 第 5 题）

正确答案是 `x=(int)(x*100+0.5)/100.0;`

| 卷别 | 该选项是第几个 |
|---|---|
| 我们的 B 卷 | **D** |
| 第三方来源 | **B** |

来源答案表写 `B`。直接抄 → 我们这卷标成 B（错误）。正确答案是 **D**。

2019 抽查第 6、7、8、12、20 题，**选项顺序全部被打乱**，是系统性的，不是个例。

---

## 二、正确做法：按选项内容映射

对**每一道题**：

```
① 取来源答案字母，找到来源里该字母对应的【选项内容】
② 在我们的 paper.md 里找【同样内容】的那个选项
③ 它的字母才是本卷答案
```

举例（2019 Q7）：

```
来源：A.冒泡  B.直接插入  C.快速  D.归并      答案 C → 内容是「快速排序」
本卷：A.快速  B.直接插入  C.归并  D.冒泡      「快速排序」是 A
                                              → 本卷答案 = A
```

**逐题做，不能批量套用置换规则**——每题的置换都不同。

## 三、能算的自己算一遍

映射完之后，**尽量独立验算**。这是唯一能发现「来源本身错了」的手段。

| 题型 | 验算方式 |
|---|---|
| 单选 1–15 | 直接算：表达式求值、组合计数、图论、数列 |
| 阅读程序 | **实际编译运行**程序，代入题给输入 |
| 完善程序 | 把候选答案填进代码，编译运行，看哪个得正确结果 |

**算不出来的，在交付报告里明确标注「仅映射，未验算」。** 不要含糊过去。

> 2019 的现状：单选 1–15 已逐题独立验算；阅读程序与完善程序 28 题**只做了映射**。
> 这个范围写进了 `meta.json` 的 `answer_source`。

---

## 四、写到哪两个地方

| 位置 | 形式 |
|---|---|
| `paper.md` 题块注释 | `answer: C` |
| `meta.json` | `"answer": "C"` |

```markdown
<!-- qid: csp-s1-2019b-001 | type: single_choice | score: 2 | answer: C | tags: topic:lang -->
```

**两处必须一致**，`validate.py` 强制检查。

### 取值规则

| 题型 | 取值 |
|---|---|
| `single_choice` | `A` / `B` / `C` / `D` |
| `true_false` | `T`（正确）/ `F`（错误） |

校验器会查取值是否与题型匹配。

> **判断题注意**：原卷只写「（ ）」，选项「正确/错误」是**页面自动补的**，
> 不要往 `paper.md` 里写选项。`answer` 填 `T` 或 `F`。

## 五、答案缺失怎么办

**留 `null`，不要编。**

| 情况 | 处理 |
|---|---|
| 该年没有答案文件（2020、2025） | 全部 `answer: null`，题块注释里**省略** `answer` 字段 |
| 只有部分答案 | 有则填，无则空 |
| 答案看不清 | 标存疑，不要猜 |

页面有兜底：没答案的题照样能作答，只是提示「本题暂无答案，无法判分」，
且不计入对错统计。

## 六、记录来源

`meta.json` 里必须写清答案的来历：

```json
"answer_source": {
  "kind": "mapped",
  "from": "https://www.cspfirstround.com/paper/csps-2019",
  "note": "该来源的选项顺序与本卷不同（疑为 A 卷），答案已按选项内容逐题映射回本卷；单选题 1-15 另行独立验算一致。判断题 T=正确 F=错误。"
}
```

`kind` 取值：

| 值 | 含义 |
|---|---|
| `official` | 官方答案文件（如 2023/2024 的答案 PDF） |
| `mapped` | 第三方来源，已按内容映射 |
| `derived` | 自行验算得出 |
| `none` | 无答案 |

**这个字段是给核验员和后续使用者看的**——他们要靠它判断可信度。

## 六之二、题解怎么写（★ 交付时保证同步）

每题正文末尾有一个**题解块**，与注释一起构成「机器读注释、人读题解」的两面
（格式逐字规格见 [SPEC.md](../../SPEC.md) 3.9）：

```markdown
> **题解**
> 答案：C
> 解释：32 位整型占 32 ÷ 8 = 4 个字节，A 项的 32 是把「位」当成了「字节」。
```

争议题在解释之后再追加一行：

```markdown
> **题解**
> 答案：√
> 解释：……
> 争议：原卷印的数组是 `char st[100]`，与题干问的长度自相矛盾；本卷按……作答，依据是实跑。
```

**四条规矩：**

1. **不要手改 `paper.md` 里的题解块。** 它由 `meta.json` 派生：
   `答案：` ← `answer`（判断题 `T→√`、`F→×`），`解释：` ← `answer_note`，
   `争议：` ← `dispute_note`。改完 `meta.json` 后跑同步：
   ```powershell
   uv run python tools/tag_questions.py 题库/csp-s1/2021
   uv run python tools/tag_questions.py 题库 --check    # 只检查
   ```
2. **每题都写 `解释：`。** v1.5 起 `answer_note` 是**必填**——只要该题有答案，
   就要写清「为什么是这个答案、其它候选为什么不成立」。文字规范见
   [11-题解写作.md](11-题解写作.md)，自检跑 `tools/lint_notes.py`。
3. **`争议：` 只给争议题写**（与来源冲突 / 题面与答案不自洽 / 答案不唯一或答案源存疑，
   判据见 `协作/需求/02-题解标签.md` 附二 + v2 附则）。要写清对方给什么、本卷取什么、
   依据是什么，**不得只写「有争议」**。程序输出、变量名用反引号，**不得**用围栏代码块。
4. **题目没有答案（`answer: null`）时整个题解块不写**，`answer_note` / `dispute_note`
   也都不写——没答案就是没有，不得编造。

> 答案没到位就先别写解释：题解是答案的下游，答案改判后必须重跑同步，
> 否则 `validate.py` 会报「题解里的答案与 meta 不符」。

### 组级「程序说明」（v1.5 新增）

「整段代码在求解什么」不属于任何小题，写在**大题组**上：

- 存 `meta.json` 顶层 `groups[]`：`{ "name": "阅读程序(1)", "section": "part2", "program_note": "……" }`，
  `name` 与 `questions[].group` 逐字一致；
- 落到 `paper.md` 该组的 **material 区**：代码块之后、本组第一个 `####` / `#####` 之前
  （插错位置会被并进上一题，见 [03-结构层级.md](03-结构层级.md) 的悬空内容一节）；
- 60~500 字，学员视角；**与答案无关**——没有答案源的卷照样能写、也该写。
