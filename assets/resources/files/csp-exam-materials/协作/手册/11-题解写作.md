# 11 · 题解写作

**这一篇是 v1.5 起「解释 / 争议 / 程序说明」怎么写**的唯一标准。格式规格在
[SPEC.md](../../SPEC.md) 3.9，字段在 [08-元数据.md](08-元数据.md)，这里只管**文字**。

参考件是 `题库/csp-j1/2019/`（`csp-j1-2019b`，43 题 + 5 段程序说明），
下面所有范例都取自它，可直接对照。

---

## 一、面向谁

**面向学员**——不是给同事看的说明，也不是给审计看的证据链。

衡量标准只有一句：**他读完能不能自己复算一遍，或者把「为什么对、其它为什么不成立」
复述出来。** 做不到就说明写得太虚。

所以：

- 用学员的词汇：可以写「约数个数」「深度之和」「抽屉原理」，不要写「口径」「裁决」
  「本库」「依据核验报告」。
- 把中间步骤摊开：别写「显然」「易得」，那是给已经会的人看的。
- 不评价题目、不点评原卷排版、不解释我们自己的转写选择——学员不关心这些。

---

## 二、长度与结构

| | |
|---|---|
| 一般 | **1~4 句**，30~200 字最常见 |
| 程序题 | 可以更长，需要把「正确候选为什么对 + 主要干扰项为什么不成立」讲完 |
| 上限 | **800 字**（程序说明上限 500 字），超了机器会拦 |
| 短于 | 20 字机器会拦——那就等于没解释 |

**宁可短而准，不要长而空。** 一句「共 21 公里不超上限，消耗 3 × 600 + 2 × 300 = 2400 千卡」
胜过三段「通过分析可知，我们要在约束条件下最大化目标函数」。

推荐的三段小结构（不必写齐，按题取舍）：

1. **结论一句**：这个答案是怎么来的（一个算式、一个判据、一段代码行为）。
2. **细节一段**：把算式/判据代进去算给人看，或指出代码里起作用的那一两行。
3. **排除一段**：主要干扰项为什么不成立（有把握时写；拿不准就别硬编）。

---

## 三、必写要素：得出答案的关键一步

**这是「解释」与「答案」的分界线。** 只重复答案等于没写；关键一步必须能让学员
自己验一遍。四种关键一步，至少要有一种：

| 题型 | 关键一步是什么 |
|---|---|
| 知识型单选 | 判据是什么（哪个表、哪条定义、哪个奖项管什么），以及别的选项为何不对 |
| 计算型单选 | **算式**：把数字代进去的过程写全（`Σ(i+1)² = 385`、`3 × 6 + 2 × 3 = 21`） |
| 判断题 | 主张为真/为假的**理由**；主张为假时给**反例**（具体输入 + 实际输出） |
| 阅读程序 | 程序里真正起作用的那几行做了什么；输入到输出的那条因果链 |
| 完善程序 | 把候选**代进去**会怎样（输出变成什么），或者它为什么必然破坏题面要求 |

程序题（阅读程序 + 完善程序）还多一条：**说清「其它候选为什么不成立」**。
学员在考场上面对的是四个长得差不多的表达式，只告诉他哪个对，等于没帮他。

> **能用实跑就用实跑。** 「输入 `1 2`、`1 3` 时 a[1] 已经是 2，所以第 15 行照样执行」
> 比「条件与大小关系无关」有说服力得多——而且这句话可以复核。

## 四、五种题型的范例（均取自 `csp-j1-2019b`）

### 4.1 单选 · 知识型（`csp-j1-2019b-015`，答案 C）

> 图灵奖由美国计算机协会（ACM）于 1966 年设立，被公认为计算机科学领域的最高奖项，选 C。A 项鲁班奖是中国建筑行业的工程质量奖，B 项普利策奖是新闻与文化领域的奖项，D 项诺贝尔奖没有设数学或计算机奖项，都与题意无关。

**好在哪**：先给判据（谁设立、什么地位），再一句话否定三个干扰项——知识型题最常见的失分点
就是「把奖张冠李戴」，所以逐个点名最有效。全程没有一个字的废话。

### 4.2 单选 · 计算型（`csp-j1-2019b-013`，答案 D）

> 倒过来看不变，要求第 1 位与第 5 位互为倒置、第 2 位与第 4 位互为倒置、中间第 3 位倒过来还是自己。能倒视成数字的只有 0、1、6、8、9 五个，其中中间位要自对称，只有 0、1、8 三种；两对对称位各自有 0↔0、1↔1、8↔8、6↔9、9↔6 五种配法。总数 = 3 × 5 × 5 = 75，选 D。A 项 60、C 项 100 都没有正确体现「中间位 3 种、两对对称位各 5 种」这个结构，B 项 125 = 5³ 相当于只要求每一位都能倒视、漏掉了成对约束。

**好在哪**：把「5 位」按对称性拆成「中间 1 位 + 两对 2 位」，这是解题的真正结构；
算式写全（3 × 5 × 5）；干扰项按**它错在哪个环节**点评，而不是笼统说「不符合」。

### 4.3 判断题（`csp-j1-2019b-017`，主张成立，答案 √）

> 第 8 行改成 `i = 0` 后，第 9 行第一次循环就要算 `n % i`，也就是对 0 取余；整数除零在 C++ 里是未定义行为，程序会崩。实跑验证：把该行改成 `i = 0`、其余一字不动重新编译，输入 `abcd`，进程异常退出，退出码 `-1073741795`，即十六进制的 `0xC0000094`，正是整数除零异常。故主张成立，填 √。

**好在哪**：判断题必须落到「真 / 假」两个字上（首句给机理、末句给结论），
中间用**实跑**兜底——退出码可以复核，学员也能自己试。
主张为假时同理，要给**具体反例**：

> ……实跑反例：n = 1、m = 1，输入 `1 1`，第 13 行条件成立，执行 `a[1] = 1`、`b[1] = 1`，于是 a[1] 与 b[1] 同时大于 0。穷举 n ≤ 4、m ≤ 4 的全部输入，反例大量存在，故填 ×。

### 4.4 阅读程序小题（`csp-j1-2019b-020`，答案 C）

> 能在哪些位置动手完全由长度决定：只要 i 能整除 n，就处理第 i 个字符，所以「有多少个字符可能改变」就等于 n 的约数个数。18 的约数是 1、2、3、6、9、18，共 6 个，选 C。实跑多组长度为 18 的输入，实际改变的字符数最多都是 6。A 项 18 是「每个字符都可能变」的松上界，B 项 10、D 项 1 与约数个数无关。

**好在哪**：先把程序行为压缩成一句话（**只有约数下标会被处理**），
再把它变成数学对象（约数个数），最后代入具体数字。
这正是阅读程序题的通用套路：**程序 → 规律 → 数字**。

### 4.5 完善程序小题（`csp-j1-2019b-035`，答案 D）

> 四个递归调用按顺序填四个象限：第 15 行 `x, y + step` 是右上、第 16 行 `x + step, y` 是左下，第 17 行带 `!t` 的必然是右下，那么第 14 行的②就是左上角，坐标正是 (x, y)，选 D。实跑代入：填 `x, y` 时 n = 2 输出的 4 × 4 矩阵与题面逐位相同；填 `x - step, y` 或 `x - step, y - step` 会把数据写到方块外（输出为空），填 `x, y - step` 则把矩阵整体错位，与题面不符。

**好在哪**：完善程序的空**几乎都能靠上下文排掉**——先指出另外三个递归各管哪个象限，
这一空就没有第二种可能；再用**把候选代进去实跑**的结果收尾（这一步是这类题的判据）。
**每个候选都点一句**，而不是只说正确的那个。

## 五、组级「程序说明」怎么写

（格式与落点见 [SPEC.md](../../SPEC.md) 3.9 的组级部分；这里讲文字。）

一段 60~500 字，讲四件事：

1. **输入是什么、输出是什么**（学员第一眼要能对上题面）。
2. **这段代码在求解什么**（用一句话概括任务；能报出算法名就报：二分、递推、贪心、
   DP、计数排序、分治、笛卡尔树…）。
3. **关键做法**：程序用什么手段做到这件事（分四个象限递归、按区间最小值建树、
   用 `ord[]` 记下标再按 `res[]` 回填…）。
4. **理解这一组题要抓住的一两点**（哪个细节决定成败：约数个数、`a[i]` 与 `b[i]`
   的含义不同、比较次数 = 深度之和…）。这一条最容易被漏掉，也最有用。

**不要写成逐行注释**，也不要复述代码。范例（`csp-j1-2019b` 阅读程序(1)）：

> 这段程序读入一个不含空白的字符串（`scanf("%s")`），然后按 1 到 n 的下标逐个检查：凡是下标 i 能整除串长 n 的位置，如果那一位是小写字母就改成大写，其余字符原样保留，最后把整个字符串输出。换句话说，它做的是「把下标为串长约数的那些小写字母变大写」。理解本题要抓住两点：一是被处理的位置只由串长的约数决定、与字符内容无关，所以「有多少个字符可能改变」就等于串长的约数个数，这一组的判断题与选择题全都围绕它展开；二是判断大写用的条件写成 `c >= 'a'`，只对小写字母成立，因此全大写输入输出不变，而输入含数字、符号也不会出错。

**注意**：程序说明在**组内 material 区**，与题干是两块地方——所以里面**不要写
「第 20 题」这类交叉引用**（会撞 test_viewer.js 的「题面不含题干」不变量，
引用组内题目改用「这组的判断题与选择题」这样的说法）。引用**行号**（「第 12 行」）
是可以的，学员要靠它定位代码。

## 六、争议行怎么写

**只有符合上面判据的题才写**（与来源冲突 / 题面与答案不自洽 / 答案不唯一或答案源存疑，
见 `协作/需求/02-题解标签.md` 附二 + v2 附则）。写的时候四件事缺一不可：

```
对方是谁 → 对方给什么 → 本卷取什么 → 依据是什么
```

范例（`csp-j1-2019b-021`）：

> 原卷第 21 题问「长度为（ ）时至多 36 个字符不同」，而程序里读入字符串的数组定义是 `char st[100]`，长度 100000 的输入根本放不下，按卷面严格推，第四项无法被程序正确处理，题面自身是矛盾的。本题只能按「不同字符数 = 字符串长度的约数个数」这一数学关系作答，四个选项里只有 100000 的约数个数是 36；为验证这一点，另把 `char st[100]` 放大成 `st[200005]`（其余逻辑一字不动）实跑，才真得到 36 个不同字符。

**依据必须可复核**：写出实跑的关键输入与输出（`输入 1 2 和 1 3，输出 4`）、
或量化实测的方法（`400 dpi 量墨迹游程`）。**不得只写「有争议」而不给依据**——
那等于把矛盾丢回给学员。

拿不准就问自己一句：**「学员照卷面能不能推出答案？」** 推得出、只是呈献方式不同
（排版、标点、矩阵写法），就**不写**；推不出、或会让他对答案产生怀疑，就**写**。
**犹豫时倾向写**——多一栏只是多一段说明。

## 七、禁用

| 禁止 | 原因 |
|---|---|
| 围栏代码块 ```` ``` ```` | 题解块带 `> ` 前缀，围栏会干扰 `validate.py` 的代码块行号扫描；展示输出用行内代码 `` `83` `` |
| 核验报告的章节号（`§3.1`、`见 3.2 节`） | 学员没有那份报告，看不懂指向 |
| 内部协作用语：`本库`、`我的处理`、`待决`、`R0`、`本任务`、`协作/`、`核验报告` | 这些只在本库的协作流程里有意义 |
| 对命题质量、原卷排版、转写方式的评价 | 学员要的是解题，不是我们的工作日志；有意见写进 `协作/待决/` |
| 编造 | **拿不准的不许编**。写出能确认的部分，把不确定的追加进 `协作/待决/<paper_id>.md` |

上面第一、三、四类由 `tools/lint_notes.py` 机器检查，第五类只能靠自觉。

## 八、允许

- **`$...$` 行内公式**：同步工具会先把题解块从正文里剥离再推导 `feat:` 标签，
  所以公式**不会**误加 `feat:formula`。`$` 必须成对（机器会查）。
- **行内代码**：变量名、关键字、输出、字符串一律用反引号（`` `char st[100]` ``、
  `` `n % i` ``）。这既是规范（SPEC 3.5），也最好读。
- 中文全角标点和「」引号；算式里的乘号写 `×`、减号写 `−` 或 `-`，前后加半角空格。
- 上下标直接用 Unicode（`2⁵`、`log₂`、`Σ`），比写 `$2^5$` 更短也更好读。

## 九、依据从哪来

1. **优先 `协作/核验/<paper_id>.md`。** 那里有逐题结论与实跑输出（`g++` 真编译真运行、
   DP 求最优、穷举找反例）。照它写，**不得引入报告里没有的说法**。
2. **报告没覆盖的题自己推导，并且实际验算**：
   - 程序题：把代码抄成 `.cpp` 真编译真运行。编译器
     `C:\msys64\ucrt64\bin\g++.exe`，`g++` 已在 `PATH` 上。
   - 计算题：把算式写进 `python`（`uv run python`）跑一遍再抄进解释。
   - 组合/计数题：宁可写枚举脚本，不要凭感觉报数字。
3. **拿不准的不许编。** 写出能确认的部分，把不确定的**追加**进
   `协作/待决/<paper_id>.md`（追加，不要覆盖别人写的内容），并在交付报告里列出。

## 十、自检

```powershell
# 1. 文字规范（长度、句末标点、首尾空白、围栏、内部协作用语、$ 成对）
uv run python tools/lint_notes.py 题库/csp-j1/2019

# 2. 同步到 paper.md（改完 meta.json 必跑）
uv run python tools/tag_questions.py 题库/csp-j1/2019
uv run python tools/tag_questions.py 题库/csp-j1/2019 --check   # 幂等：更新 0 道

# 3. 结构与 meta 的一致性（含组级程序说明）
uv run python tools/validate.py 题库/csp-j1/2019
```

三条都退出码 0 才算写完。写完还要**亲眼回看** `paper.md`：
题解块首行、全角冒号、判断题 `√`/`×`、块前恰好一空行、程序说明在代码块之后。
