## 标签与同步

```powershell
# 自动补 feat: 标签 + 把 meta.json 的字段（含题解块）同步到 paper.md
uv run python tools/tag_questions.py 题库/csp-s1/2020

# 只检查是否已同步，不写入
uv run python tools/tag_questions.py 题库 --check

# 标签词表：从 TAGS.md 生成到 tags.json 与页面
uv run python tools/gen_tags.py
uv run python tools/gen_tags.py --check
```

> **题解块也由它同步**（[SPEC.md](../../SPEC.md) 3.9）：`答案：` 来自 `answer`，
> `解释：` 来自 `answer_note`，`争议：` 来自 `dispute_note`；大题组的
> `> **程序说明**` 来自顶层 `groups[].program_note`，落在代码块之后、第一个分栏之前。
> **改了这些字段必须重跑**，否则 `validate.py` 会报「题解里的答案与 meta 不符」。
> 不要手改 `paper.md` 里的题解块与程序说明块——下次同步就被覆盖。

## 题解文字自检（v1.5）

```powershell
# 解释 / 争议 / 程序说明的写作规范：长度、首尾空白、句末标点、围栏、内部协作用语、$ 成对
uv run python tools/lint_notes.py 题库/csp-j1/2019
uv run python tools/lint_notes.py 题库            # 全库，有违例则退出码 1
```

用法与 `tag_questions.py` 一致（可传卷目录或 `题库`）。规范全文见
[11-题解写作.md](11-题解写作.md)。**它查的是文字本身**，`validate.py` 查的是结构，
两者都要过。输出里的 `✓ 题库/…（解释 43 / 争议 1 / 程序说明 5）` 是**计数**——
一条题解都没写的卷也会显示 ✓，看计数才知道干了多少活。

| 报错 | 处理 |
|---|---|
| `有 answer 却没有 answer_note（每题都要解释）` | 补解释（v1.5 起每题都要），改 `meta.json` 后重跑同步 |
| `太短（N 字，下限 20）` | 解释没写清「为什么」，补上关键一步（算式/判据/实跑输出） |
| `太长（N 字，上限 800）` | 砍到最必要的一句话；程序说明上限是 500 |
| `句末不是中文句末标点` | 补 `。`（不要用 `.` 或 `;` 收尾） |
| `出现内部协作用语「…」` | `本库` / `我的处理` / `待决` / `R0` / `本任务` / `协作/` / `核验报告` / `§数字` 都不该出现——学员看不懂 |
| ``$` 不成对` | 行内公式补上收尾的 `$` |
| `含围栏代码块` | 改成行内代码（题解块内禁止 `` ``` ``） |

## 校验（交付前必须全过）

```powershell
# 单份 / 整个题库
uv run python tools/validate.py 题库/csp-s1/2020
uv run python tools/validate.py 题库
```

**检查项**：题号连续性、题块注释与 `meta.json` 一致、分节分值、图片引用与孤儿图、
图片替代文本、代码块行号格式与连续性、标题层级、标签是否在受控词表内、
源 PDF 副本摘要、中间产物残留、**题解块**（有答案必须有题解、有答案必须有非空
`answer_note`、首行/全角冒号/判断题 `√`·`×`、解释与 `answer_note` 逐字一致、
争议与 `dispute_note` 逐字一致且**排在解释之后**、必须是正文最后一块、块内不得有围栏）、
**组级程序说明**（每个 `questions[].group` 都要有非空 `program_note`、`groups[]` 里不许有
没被引用的组名、每组 material 区恰好一个 `> **程序说明**` 且内容逐字一致）。

**看退出码，不看「通过」两个字**：

```powershell
uv run python tools/validate.py 题库
$LASTEXITCODE      # 必须是 0
```

## 页面性能体检

```powershell
uv run --with playwright python tools/perf_page.py
```

导入全部 14 卷（600 张题卡）后量：打开耗时、点击判题的 JS 耗时与到下一帧的耗时、
字号放大后的点击耗时、搜索框逐字输入耗时，并报告长任务。

**没有阈值断言**，是给人看的体检表——数值明显变大就说明有回退。
判读要点：

| 指标 | 正常量级 | 说明 |
|---|---|---|
| 打开（导入→DOM→首帧） | 约 0.5 s | 主要花在解析 14 份 `paper.md` 与建卡 |
| 点击判题 **JS** | < 1 ms | **必须与题目总数无关**。若涨到几毫秒且随卷数变多，说明又在全表扫描 |
| 点击判题 到下一帧 | 几 ms ~ 20 ms | 含样式重算与重绘；一帧约 16 ms，波动正常 |

## 排错

| 报错 | 原因 | 处理 |
|---|---|---|
| `题块 tags 与 meta 不符` | 两处标签不同步 | 跑 `tag_questions.py` |
| `标签不在受控词表中` | 用了词表外的标签 | 走标签申请流程，不要自己加 |
| `代码块行号不连续` | 抄漏了行或空行没占行号 | 回原卷逐行核对 |
| `图片引用指向的文件不存在` | 路径错或文件没放对 | 图片必须在 `assets/` 下 |
| `assets/ 中未被引用的孤儿图片` | 图放了但没在 md 里引用 | 补引用或删图 |
| `源 PDF 副本摘要不符` | 副本被改过 | 重新复制原件、重算摘要 |
| `组别目录名与 meta.exam 不符` | 路径与元数据不一致 | 检查目录名与 `exam`/`year` |
| `题块 score 与 meta 不符` | 两处分值不同步 | 以 `meta.json` 为准同步 |
| `有 answer 却没有题解块` | 题解块没生成 | 跑 `tag_questions.py` 该卷 |
| `没有 answer，不得有题解块` | 该题没答案却写了题解 | 删掉题解块（或补上答案后重跑同步） |
| `有 answer 的题必须有非空 meta.answer_note` | 只写了答案没写解释 | 补 `answer_note`（v1.5 起每题都要），再重跑同步 |
| `题解里的答案与 meta 不符` | 手改了题解，或改了答案没重跑同步 | 跑 `tag_questions.py` 该卷 |
| `题解块的解释与 meta.answer_note 不符` | 同上，改的是 `解释：` | 跑 `tag_questions.py` 该卷 |
| `题解块的争议与 meta.dispute_note 不符` | 同上，改的是 `争议：` | 跑 `tag_questions.py` 该卷 |
| `meta.dispute_note 非空，题解块缺少 争议： 行` / `meta.dispute_note 为空，题解块不应有 争议： 行` | 争议行的有无没跟上 meta | 跑 `tag_questions.py` 该卷 |
| `题解块里 争议： 排在 解释： 之前` | 手改了顺序 | 顺序固定为 答案 / 解释 / 争议，重跑同步 |
| `题解块首行应恰好是 …` / `第二行应是 …` | 少了 `> ` 前缀或冒号用了半角 | 按 SPEC 3.9 改正后重跑同步 |
| `题解块之后还有内容` | 题解块不是正文最后一块 | 把后面的内容移到题解块之前 |
| `题解块第 N 行出现围栏代码块` | 解释里用了 ` ``` ` | 改成行内代码 |
| `题目引用了大题组 X，meta.groups 里却没有对应项` | 组级程序说明没写 | 给 `meta.groups` 补 `{name, section, program_note}` |
| `meta.groups 里 X 的 program_note 为空` | 组级说明写空了 | 补 60~500 字的程序说明 |
| `大题组 X 的题面区缺少 > **程序说明** 块` | 没同步 | 跑 `tag_questions.py` 该卷 |
| `大题组 X 的题面区有 N 个 > **程序说明** 块` | 手抄了第二份 | 只留一个，其余删掉后重跑同步 |
| `大题组 X 的程序说明与 meta… 不符` | 手改了程序说明块 | 改 `meta.groups[].program_note` 后重跑同步 |
