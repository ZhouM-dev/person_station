# 01 · 源文件判定

**开工第一件事**：确定源 PDF 是哪一类。这决定了你走哪条流程，判错会白干。

---

## 先跑勘察

```powershell
uv run --with pymupdf python tools/survey_sources.py
```

输出示例：

```
文件                   页数  文本层        可信     首行摘录
2021-试题.pdf          16  有          是      CCF CSP-S 2021 第一轮C++语言试题
2025-试题.pdf          19  有          否(广告)  专注名校拔尖创新人才培养
```

**只看「可信」这一列**：

| 可信 | 含义 | 走哪条流程 |
|---|---|---|
| `是` | 文本层就是题目 | 文本层流程（§二） |
| `否(广告)` | 文本层是推广页，题目在底层图像里 | **扫描件流程（§三）** |
| `—` | 根本没有文本层 | 扫描件流程（§三） |

---

## 一、为什么不能只看「有没有文本层」

有文本层**不等于**文本层是题目。

`2025-试题.pdf` 有 19 页文本层，但内容全是「自主选拔在线」的公众号推广页，
真正的试卷是底下的扫描图。

**按文本层直接转的后果：得到 19 页广告，题目一道不剩。**

所以判断标准是**内容**，不是有无。勘察脚本用关键词（微信公众号、咨询热线、
zizzsw 等）统计每页，超过 60% 是这类内容就判「不可信」。

---

## 二、文本层流程

适用：2021、2022、2023、2024 试题；2023、2024 答案。

```
① mcp__cherry-tools__to_markdown 转出草稿
② 逐页对照原 PDF 校对  ← 关键，不能省
③ 按 03-结构层级.md 重排为题块格式
④ 插图另行提取（05-图片提取.md）
```

### ② 为什么必须逐页校对

转换器不懂题目结构，会把这些弄乱：

| 症状 | 实例 |
|---|---|
| 代码缩进丢失、被排成表格 | 2021 阅读程序的代码被转成了 Markdown 表格，缩进全无 |
| 上下标错位 | `F₁`、`O(n²)` 变成 `F1`、`O(n2)` |
| 表格串行 | 选项被塞进单元格 |
| 页眉页脚混入正文 | 「CCF CSP-S 2021 第一轮 C++语言试题 第1页，共16页」 |

**转换器出的稿是草稿，不是成品。** 逐页比对是这一步的全部价值。

## 三、扫描件流程

适用：2019、2020、2025 试题；2021、2022 答案。

PDF 是图像，没有可提取的文字，只能渲染成图后**逐页识读**。

```
① 渲染成图
   uv run --with pymupdf python tools/render_pages.py 题目/<文件>.pdf 题库/<组别>/<年份>/_pages --dpi 200

② 用 Read 工具逐页看图，人工转写
   ← 不要试图用命令行提取文本，一个字也提不出来

③ 提取插图（05-图片提取.md）

④ 删掉 _pages/ 中间产物
```

### 识读要点

- **dpi 200 够用**。再高只是浪费，字迹在 200dpi 下清晰可辨
- **看不清就标存疑**，不要猜。写进交付报告的「存疑项」
- 拿到手的 PDF 若本身缺页、串页，如实记录，**不要用其它来源的内容填补**

---

## 四、判定记录要写进交付报告

`协作/交付/<paper_id>.md` 里写明：

```markdown
## 源判定
- 文件：题目/2020-试题.pdf
- 类型：扫描件（survey_sources.py 报「无(图像)」，13 页）
- 流程：SPEC §5.2
```

这样核验员能复核你的判断。
