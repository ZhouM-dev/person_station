  `a∈[0,255]×b∈[1,120]×d∈{b,b+1,500,1000}`、`a∈[0,255]×b∈{1,200,500,999,1000}×d∈{b,1000}`、

- **第 18 题「时间复杂度是 $O(b)$」**：给程序加了运算量计数器，实测**同一 `b` 下运算量随 `d` 线性增长**：
  ```
  a=1 b=1000 d=1   work=1000
  a=1 b=1000 d=2   work=2000   (x2)
  a=1 b=1000 d=512 work=381440 (x1.70676/每次翻倍)
  ```

  a=1 b=496 d=496 work=123502  work/b=248.99  work/(b*log2 b)=27.81

### 3.4 阅读程序(3) 第 27–32 题 ★

源码 → `r3.cpp`。

```
> r3.exe  输入 "10"

> r3.exe  输入 "16"

```

**关键事实：`h[1]` 到底合并出了什么序？** 用**字符串版**程序（与数值版合并顺序完全相同，
但把每步结果存成 `std::string`）独立复现，并与四种遍历逐一比对：

```
===== n = 10 =====
程序 h[1] 实际合并结果 : 0001010011   值=83
中序遍历              : 0001010011   值=83     <== 与 h[1] 相同
先序遍历              : 0100010101   值=277
后序遍历              : 0000110110   值=54
下标(BFS)序 1..n      : 0110101000   值=424
p[] 素数表 1..n       : 0110101000

===== n = 16 =====
程序 h[1] 实际合并结果 : 0000101100011010   值=2842
中序遍历              : 0000101100011010   值=2842   <== 与 h[1] 相同
先序遍历              : 0100001011001100   值=17100
后序遍历              : 0000011101000110   值=1862
下标(BFS)序 1..n      : 0110101000101000   值=27176
```

**结论：`h[1]` 严格等于中序遍历串**，与选项值的对应关系一目了然：

| 选项 | 值 | 对应哪种序 |
|---|---|---|
| **A** | **83** | **中序**（= 程序实际行为） |
| B | 424 | 下标(BFS)序 |
| C | 54 | 后序 |
| D | 110101000 | 424 的二进制写法（无前导零） |

  `solve()` 的 `sort` 是 $O(n\log n)$，合计 $O(n\log n)$ → **T（√）**，与官方一致。

## 四、第 30 题与第 31 题 —— 明确结论 ★★

### 4.1 结论

| 题 | 现在记的 | **应改为** | 是否必须同时改 |

**两题必须同时改。** 只改一题会得到一组自相矛盾的答案。

### 4.2 理由（三条独立证据）

**证据一 · 编译运行（硬件事实）**
卷面代码原样编译运行，输入 `10` 输出首行 `83`。`83` 只对应选项 `A`；官方给的 `C`（54）**不是**这个程序的输出。
（`h1` 的算法是 `h1 = h1 * 2^k + 后继`，且 `K1 = 0`，所以 `h[1].h1` 恰好等于该 01 串的二进制值，
不是哈希碰撞出来的巧合。）

**证据二 · 字符串版复现（结构事实）**
把 `h[i] = h[2*i] + h[i] + h[2*i+1]` 用字符串重放，`h[1]` 与**中序遍历串逐字符相同**（n=10、n=16 都验证过）。
「左子树 + 自身 + 右子树」就是中序的定义；后序应写成 `h[2*i] + h[2*i+1] + h[i]`，代码不是那样写的。
所以第 30 题的正确答案是 **C（中序）**，第 31 题首行是**中序串的值 83 = A**。

**证据三 · 官方那对答案自身矛盾（逻辑事实）**
设「合并顺序」为某种遍历序，`h[1]` 就是该序的 01 串，于是两题**必须由同一种序同时决定**：

| 若第 30 题选 | 则第 31 题应为 | 官方给的第 31 题 |
|---|---|---|
| A 二叉树的 BFS 序 | **B（424）** | C ✗ |
| B 先序遍历 | 277（不在选项里） | C ✗ |
| **C 中序遍历** | **A（83）** | C ✗ |
| D 后序遍历 | C（54） | C ✓ |

官方给的是 **30=A、31=C** —— 这等于「第 30 题按 BFS 序、第 31 题按后序」，**任何一种统一的读法都得不到这一对**。
官方这一对**自相矛盾**；而 **(30=C, 31=A)** 是唯一与卷面代码相符的自洽组合。

**旁证 · 选项就是照三种遍历设计的**：第 31 题 `A=83`（中序值）、`B=424`（下标/BFS 序值）、
`C=54`（后序值）、`D=110101000`（424 的二进制写法）——三个真遍历值 + 一个写法干扰项。
出题人心中「正确」的那个是 83，官方表把它填到了 C 的位置，正好和第 30 题对调。

### 4.3 可直接用作题解「解释」的文字

**第 30 题（应选 C）**

> `solve()` 里每次合并都写成 `h[i] = h[2*i] + h[i] + h[2*i+1]`，也就是把「左子树的串 + 结点本身 + 右子树的串」首尾相接，这正是二叉树**中序遍历**的定义；`h[1]` 最终得到的就是整棵树的中序 01 串。注意外层循环 `for (int i = n; i; --i)` 让 `i` 从大到小只是为了**自底向上**计算、保证算 `i` 时两个儿子已经算好，它描述的是**计算的先后**，不是拼出来的串的顺序——按下标递减算，恰恰是 BFS 序的**逆序**，所以 A 也不成立。
