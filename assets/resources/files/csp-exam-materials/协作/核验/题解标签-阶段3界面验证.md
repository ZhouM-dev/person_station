## 四、`UI.showSolution = false` 是怎么做到的（**没有动真文件**）

**方法：临时副本。** 全程未修改 `F:\ai\试题\viewer.html`。

1. 读出真 `viewer.html` 全文；
2. 断言目标串在全文命中**恰好 1 次**（防替换错位）：
   `assert src.count("showSolution:   true,") == 1`
3. 仅把 `showSolution:   true,` 替换为 `showSolution:   false,`，写入
   `%TEMP%\tiku-verify-sol\viewer-showSolution-false.html`（**仓库之外**）；
4. 以 `file://` 打开该副本，同样注入 2019 数据，读数 + 截图。

选这个做法而不是「加载后用脚本改配置对象」，是因为它顺带验证了**开关在页面初始化路径上确实生效**
（`applyUiFlags()` 在加载时就把 `ui-hide-solution` 加到 `body`），比事后改对象更强。

两种做法我都做了：副本加载时 `body` 已是 `ui-hide-topic-tags ui-hide-solution`（初始化路径生效）；
同一副本内再 `UI.showSolution = true; applyUiFlags(); refreshQuiz();` 题解即恢复（反向对照）。

  2022 卷 43 题同样 0 泄漏。
- **判断题显示 `√`/`×`**：12/12 通过，且与 `meta.json` 的 `T`/`F` 映射逐题相等，**无一处显示 `T`/`F`**；
  2022 卷 9 道判断题同样正常。

### 发现的问题

**未发现缺陷。** 两处值得记录（均非缺陷）：

1. `showSolution=false` 时，`[data-ui="qcard.solution.toggle"]` 自身计算 `display` 不是 `none`，
   由祖先 `[data-ui="qcard.solution"]` 整体隐藏。视觉/交互正确，但**按按钮计算样式做断言会出错**。
2. `showSolution=false` 走的是 CSS 隐藏（节点留在 DOM，符合 `viewer.html:512` 「隐藏 ≠ 移除」的既有约定），
   而考试模式提交前是**根本不建节点**。两种语义不同、各自符合规格，
   但「题解在 DOM 里可读」在 `false` 状态下依然成立——若日后把该开关当成「防作弊」用，会误判。

### 一处方法论提醒（留给后续核验）

`.qcard` 的 `content-visibility:auto` 会让**屏幕外卡片的 `innerText` 返回空串**。
本阶段第一轮因此出现过一次**空转检查**（题干取到空串 → 误判「无泄漏」）。
后续任何用 `innerText` 做全列表文本断言的核验，**必须改用 `textContent`**，或先逐题 `scrollIntoView`，
并在断言里加一条「取到空串即报警」的哨兵。已在 §〇.3 与 `_verify_result2.json`（`emptyStems`）中留证。
