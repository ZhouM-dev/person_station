# 协作角色与分工

本文件定义试题库转换的**多会话协作规程**。所有参与方开工前必须先读本文件。

**规程优先级**：格式问题以 [SPEC.md](../SPEC.md) 为准，流程与权限以本文件为准。
两者冲突时，停下来问管理者，不要自行裁量。

---

## 一、为什么要分角色

剩余 6 份试卷要转，天然可以并行。但有一类文件是**共享的**：

| 共享文件 | 谁在写 | 并发的后果 |
|---|---|---|
| `题库/index.json` | 每份新试卷都要登记 | 互相覆盖，登记丢失 |
| `tags.json`、`viewer.html` 的标签表 | 新增标签时 | 三方不同步 |
| `SPEC.md`、`TAGS.md` | 规范变更时 | 规范漂移，各年产物不一致 |

而每份试卷自己的目录（`题库/<组别>/<年份>/`）是**天然隔离**的，互不干扰。

所以分工原则只有一条：**共享资源单写者，独占资源并行做。**

---

## 二、角色

### R0 · 管理者

**定位**：不参与具体转换，只做派工、裁决、登记、终验。保持中立，才能验收别人。

| | |
|---|---|
| **可写** | `题库/index.json`、`SPEC.md`、`TAGS.md`、`UI-MAP.md`、`tags.json`、`viewer.html`、`tools/*`、`协作/看板.md`、`协作/派工/*` |
| **只读** | 各年份试卷目录、`协作/交付/*`、`协作/核验/*` |
| **职责** | ① 派工并写任务书<br>② 裁决规范争议（转写员上报的问题）<br>③ 维护标签词表<br>④ 终验并登记 `index.json`<br>⑤ 维护看板 |
| **不做** | 不转写、不核验任何一份试卷 |

### R1 · 转写员

**定位**：一份试卷一个独立对话。只对**自己那一年**负责。

> **作业依据：[转写员工作手册](手册/README.md)。**
> 派工时把手册入口路径给新对话，并告知年份即可，例如：
> 「读 `F:\ai\试题\协作\手册\README.md`，你负责 CSP-S 2020 年。」
> 手册是模块化的（12 篇），改一个模块不影响其它。

| | |
|---|---|
| **可写** | `题库/<组别>/<年份>/`（含 `paper.md`、`meta.json`、`assets/`、源 PDF 副本）<br>`协作/交付/<paper_id>.md` |
| **只读** | `SPEC.md`、`TAGS.md`、`题目/*`、`资料/*`、`tools/*`、其它年份目录 |
| **职责** | ① 判定源类型（文本层 / 扫描件）<br>② 转写为 `paper.md`<br>③ 裁切插图到 `assets/`<br>④ 写 `meta.json`（含答案）<br>⑤ 复制源 PDF 进年份目录<br>⑥ 跑通校验后交付 |
| **禁止** | ⛔ 写 `index.json`（管理者登记）<br>⛔ 写其它年份目录<br>⛔ 修改 `SPEC.md` / `TAGS.md` / `tools/*`<br>⛔ **自行新增 `topic:` 标签**（见 §八） |

### R2 · 核验员

**定位**：一份试卷一个独立对话，**必须与转写员不是同一个对话**。
独立视角是核验的全部价值——同一个人复查自己的活，看不出自己的盲区。

| | |
|---|---|
| **可写** | `协作/核验/<paper_id>.md` |
| **只读** | 其余一切 |
| **职责** | ① 逐页对照原始 PDF 与 `paper.md`<br>② **独立验算答案**（程序题要真编译真运行）<br>③ 跑 `validate.py` 与两个测试<br>④ 出核验报告，明确列出不一致项 |
| **禁止** | ⛔ 修改任何试卷文件（发现问题只报告，由转写员改） |

## 三、权限矩阵

| 资源 | R0 管理者 | R1 转写员 | R2 核验员 |
|---|---|---|---|
| `题库/index.json` | **写** | 读 | 读 |
| `题库/<年份>/`（自己的） | 读 | **写** | 读 |
| `题库/<年份>/`（别人的） | 读 | 读 | 读 |
| `SPEC.md` / `TAGS.md` / `UI-MAP.md` | **写** | 读 | 读 |
| `tags.json` / `viewer.html` | **写** | 读 | 读 |
| `tools/*` | **写** | 读 | 读（可执行） |
| `协作/看板.md` | **写** | 读 | 读 |
| `协作/派工/<id>.md` | **写** | 读 | 读 |
| `协作/交付/<id>.md` | 读 | **写** | 读 |
| `协作/核验/<id>.md` | 读 | 读 | **写** |

> **一写一读原则**：每个文件只有一个角色有权写。多个对话同时写同一文件必然丢内容。

## 四、通信协议

### 目录

```
协作/
├── 角色与分工.md      # 本文件
├── README.md          # 目录用法速查
├── 看板.md            # 任务总表（R0 写）
├── 派工/
│   └── <paper_id>.md  # 任务书（R0 写）
├── 交付/
│   └── <paper_id>.md  # 交付报告（R1 写）
└── 核验/
    └── <paper_id>.md  # 核验报告（R2 写）
```

`<paper_id>` 用 SPEC 定义的试卷 ID，例如 `csp-s1-2020`。

### 为什么按试卷分文件

如果所有任务写进同一个文件，两个转写员同时更新就会互相覆盖。
按 `paper_id` 分文件后，**每人只碰自己的文件**，并发天然安全。

### 流转

```
R0 写 派工/<id>.md
      ↓
R1 干活 → 写 交付/<id>.md  → 通知 R0
      ↓
R0 指派 R2（写进看板）
      ↓
R2 核验 → 写 核验/<id>.md
      ↓
   ┌── 通过 ──→ R0 登记 index.json → 看板置「已完成」
   └── 打回 ──→ R0 转 R1 返工 → 回到 R1 干活
```

## 五、工作单元与并行度

**一份试卷 = 一个工作单元 = 一个独立对话。**

不要让一个对话连做多年：转写是重上下文的活，连做会导致后半程质量下滑，
而且一旦出错要整批返工。

| 组别 | 年份 | 试题源 | 答案源 | 状态 |
|---|---|---|---|---|
| CSP-S | 2019 | 扫描件 | 第三方（已映射） | ✅ 已完成（样板） |
| CSP-S | 2020 | 扫描件 13 页 | 无 | ⬜ 待派工 |
| CSP-S | 2021 | 文本层 | 扫描件 30 页 | ⬜ 待派工 |
| CSP-S | 2022 | 文本层 | 扫描件 1 页 | ⬜ 待派工 |
| CSP-S | 2023 | 文本层 | 文本层 | ⬜ 待派工 |
| CSP-S | 2024 | 文本层 | 文本层 | ⬜ 待派工 |
| CSP-S | 2025 | ⚠️ 文本层是广告水印 | 无 | ⬜ 待派工 |
| CSP-J | 2019–2025 | 见 `题目/csp-j/` | 见 [手册/README](手册/README.md) | ⬜ 待派工（7 份） |

> **2025 的坑**：`2025-试题.pdf` 有文本层，但内容全是「自主选拔在线」的推广页，
> 真正的试卷是底层扫描图。**直接按文本层转会得到一堆广告、且丢失全部题目**，
> 必须走扫描件流程。详见 [README.md](../README.md)。

**并行策略**：6 份 S 卷可同时开工，但**核验要串开**——R2 与 R1 不能是同一对话，
也不建议一批全转完再统一核验，那样返工成本会堆在一起。

## 六、交付标准（DoD）

### R1 转写员——交付前必须全部满足

- [ ] `uv run python tools/validate.py 题库/<组别>/<年份>` → **退出码 0**
- [ ] `uv run python tools/tag_questions.py 题库 --check` → 通过
- [ ] `uv run python tools/gen_tags.py --check` → 通过
- [ ] **题解块已同步**：每题正文末尾有 `> **题解**` / `答案：`（判断题为 `√`/`×`）/
      `解释：`，争议题另有 `争议：`（排在 `解释：` 之后）。**题解只在 `meta.json` 里改、
      由 `tag_questions.py` 生成，不得手改 `paper.md`**（见 [SPEC.md](../SPEC.md) 3.9）
- [ ] **每题有解释、每组有程序说明**：有答案的题 `answer_note` 必填非空；
      阅读程序 / 完善程序的每个大题组都有 `> **程序说明**`（来源 `meta.groups[].program_note`，
      落在代码块之后、第一个分栏之前），见 [手册/11-题解写作.md](手册/11-题解写作.md)
- [ ] **`uv run python tools/lint_notes.py 题库/<组别>/<年份>` → 退出码 0**
      （解释与争议的长度、句末标点、内部协作用语自检）
- [ ] 源 PDF 逐字节副本已放入年份目录，`meta.json` 的 `source.sha256` 已填
- [ ] `_pages/`、`_tiles/` 等中间产物已删除（validate 会提示）
- [ ] `协作/交付/<paper_id>.md` 已填写

### R2 核验员——报告里必须包含

核验**分级**，程序题是重点：

| 内容 | 核验强度 |
|---|---|
| 阅读程序 / 完善程序（016–043） | **逐行核对代码**（行号、缩进、运算符、变量名、注释），答案**真编译真运行** |
| 判断题（12 题） | 逐题核对题干与答案 |
| 单选 1–15 | 可抽样，但每题答案要独立验算 |
| 卷首、注意事项、页眉页脚 | 抽查 |

- [ ] **逐页结论**：每一页明确写「一致」或列出问题
- [ ] **问题清单**：`页码 | qid | 转写写的 | 原件实际是 | 性质`
- [ ] **答案验算**：程序题要真编译真运行，不能用「看起来对」交差
- [ ] **改判过的题**：`meta.json` 的 `answer_note` 写明「对方给什么、本库取什么、
      依据是什么」，并已重跑 `uv run python tools/tag_questions.py 题库/<组别>/<年份>`
      让题解块跟上（题解由 `answer` 派生，见 [SPEC.md](../SPEC.md) 3.9）
- [ ] **未验算的部分必须明说**（如「第 X 题起仅映射，未验算」）
- [ ] 三项校验命令的**实际输出**（不是「已通过」四个字）
- [ ] **总体判断**：哪部分可放心用，哪部分必须重做

### R0 管理者——终验并登记

- [ ] 通读 R2 报告，确认无未解决异议
- [ ] 全套测试：`bun tools/test_viewer.js` + `uv run --with playwright python tools/test_page.py`
- [ ] 登记 `题库/index.json`
- [ ] 看板置「已完成」

## 七、异常处理

| 情况 | 处理 |
|---|---|
| 原件看不清、无法确认 | **不猜**。在 `交付/` 里列为「存疑项」，由 R0 裁决 |
| 需要新的 `topic:` 标签 | **不要自己加**。在 `交付/` 里提「标签申请」，R0 更新 TAGS.md 并跑 `gen_tags.py` 后回复 |
| 发现 SPEC 有歧义或缺失 | 在 `交付/` 里提「规范问题」，R0 裁决并更新 SPEC，**其它转写员暂停相关工作等结论** |
| 源文件本身有问题（缺页、串页） | 如实记录，不要用其它来源的内容填补 |
| 校验失败但看不懂原因 | 连带完整报错贴进 `交付/`，不要绕过或注释掉检查 |

### 铁律

1. **不猜。** 宁可标存疑，不可编造。题库是给教学用的，错答案比没答案危害大。
2. **不改共享文件。** 需要改，走上报。
3. **不跳过校验。** 校验失败就是没做完。
4. **不覆盖别人的文件。** 只写自己权限内的路径。

## 八、标签冻结

`topic:` 词表当前 15 个，锚定 [NOI 大纲（2025 年修订版）](../资料/NOI大纲-2025-考点.md) 的分类。

**转写员不得自行新增标签**，原因：标签是跨年份的全局维度，各年各自扩展会导致
同一个知识点在不同年份挂不同标签，题库就废了。

需要新标签时，在 `交付/` 里写：

```markdown
## 标签申请
- 拟新增：`topic:prob`（概率与期望）
- 理由：2021 年第 X 题考的是条件概率，现有 topic 词表覆盖不到
- 考纲依据：2.2.5 数学与其他 → 概率论（目前未单列）
```

R0 更新 TAGS.md → 跑 `gen_tags.py` → 通知全体。**在回复之前，该题先挂最接近的现有标签。**

## 九、可选角色：答案提取员

当年份的答案源**独立且体量大**时（如 2021 的 30 页扫描件答案），可单独派一个对话：

| | |
|---|---|
| **可写** | `协作/答案/<paper_id>.md` |
| **只读** | 其余一切 |
| **职责** | OCR 答案文件；**按选项内容映射**到本卷序号（见手册 06）；可验算的独立验算 |
| **禁止** | 直接改 `meta.json` 或 `paper.md`——他只产出答案数据 |

产出由**该年的转写员**合并进 `meta.json`（保持单写者）。

> **注意依赖**：答案提取需要**先有题目**才能做内容映射（A/B 卷陷阱），
> 所以这是**下游任务**，不能与转写并行开工。

## 十、年内调度自由

**模块拆分是转写员的内部实现，不是协作层的角色。**

一份试卷的转写员可以在自己那一年内用子代理并行处理选择题 / 阅读程序 / 完善程序，
以获取模块专精。但对 `paper.md` 和 `meta.json`，**他始终是唯一写者**——
子代理只产出片段，由他统一落盘。

这样既有模块分工的收益，又不会出现多个写者互相覆盖。
