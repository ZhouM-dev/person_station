# 题型与标签规范

[SPEC.md](SPEC.md) 定义了「文件长什么样」，本文件定义「每道题怎么被标识」。

标识分两层：

- **结构标签**——四个固定字段，枚举值，必填，机器可校验。回答"这题在哪一节、
  怎么作答、属于哪个大题、值多少分"。
- **内容标签**——`tags` 数组，受控词表，选填，可增长。回答"这题考什么、题干里有什么"。

判分、组卷、统计靠结构标签；按知识点检索、筛同类题靠内容标签。

---

## 1. 一道题的完整标识

以 2019 年 B 卷第 30 题为例：

```markdown
##### 第 30 题

<!-- qid: csp-s1-2019b-030 | type: true_false | score: 2 | tags: feat:lineref,feat:formula,topic:string -->

（2 分）程序运行到第 23 行时，"$j - i - 1$" 一定不小于 0。（ ）
```

拆开看：

| 部分 | 值 | 层 |
|---|---|---|
| `qid` | `csp-s1-2019b-030` | 题号标识 |
| `type` | `true_false` | 结构 |
| `score` | `2` | 结构 |
| `tags` | `feat:lineref`、`feat:formula`、`topic:string` | 内容 |

`section` 和 `group` 不写在题块里，它们由 `meta.json` 承载（一题一个组，
写在每道题上会重复 6 遍）。

---

## 2. 题号标识（`qid`）

格式：`{paper_id}-{三位序号}`

```
csp-s1-2019b-030
└──┬───┘└┬┘└┬┘
   │     │  └── 全卷连续序号，3 位补零
   │     └───── 年份
   └─────────── 考试：csp-s1（提高级第一轮）/ csp-j1（入门级第一轮）
                末尾字母为卷别，无标注则省略
```

**为什么用全卷连续序号，而不用原卷的「第几大题第几小题」：**

1. 历年原卷编号方式本身就不统一。2019 年阅读程序里的小题按 `1) 2) 3)` 在每组内
   重新计数；2021 年则从 16 一路连续编到 43。
2. 官方答案文件用的就是连续编号——2023 年答案 43 个、2024 年答案 42 个，都从 1
   排到尾。用连续序号可以直接和答案序列逐位对齐，不必做分节换算。
3. **各年结构并不一致**，序号无法用公式推算：

   | 年份 | 总题数 | 阅读程序内部构成 |
   |---|---|---|
   | 2019 | 43 | 3 组 ×（4 判断 + 2 选择） |
   | 2021 | 43 | (4+2)、(3+3)、(3+3) |
   | 2023 | 43 | 待确认（仅有答案） |
   | 2024 | 42 | 合计 17 题，与前两者均不同 |

   总量看着稳定（40 分），内部切分却逐年变化。所以**序号必须逐卷显式记录**，
   任何"第 N 题一定是阅读程序第几组"的推断都会出错。

原卷编号保留在 `meta.json` 的 `original_no`（如 `"1"`、`"2)-3"`、`"①"`），
用于回溯原卷。

## 3. 结构标签（固定字段）

### 3.1 `section` — 节

| 值 | 中文 | 卷面标题 |
|---|---|---|
| `part1` | 第一节 | 一、单项选择题 |
| `part2` | 第二节 | 二、阅读程序 |
| `part3` | 第三节 | 三、完善程序 |

### 3.2 `type` — 作答形式

**只有两个值**，取决于「考生怎么作答、机器怎么判分」，与题目难度、知识点无关。

| 值 | 中文 | 判分 | 答案格式 |
|---|---|---|---|
| `single_choice` | 单选 | 选对得分，无部分分 | `"A"` ~ `"D"` |
| `true_false` | 判断 | 判断正确得分 | `"T"` / `"F"` |

> 三节里的题都落在这两个值上：第一节全是 `single_choice`；第二节判断题是
> `true_false`、选择题是 `single_choice`；第三节（完善程序）虽然作答形式是
> "填空"，但每空给出 ABCD 四个候选、填字母即可，因此也是 `single_choice`，
> 不是 `fill_blank`。

### 3.3 `group` — 大题组

同一段材料（一段程序、一个背景）下的若干小题共享一个组名。`part1` 的题为 `null`。

| 节 | `group` 取值 |
|---|---|
| `part1` | `null` |
| `part2` | `阅读程序(1)`、`阅读程序(2)`、`阅读程序(3)` |
| `part3` | `完善程序(1)`、`完善程序(2)` |

**用途**：一组共享同一段代码，抽题时要么整组抽、要么按 `qid` 单独抽——
靠 `group` 就能把一个组的题一次捞出来，不会把题目和它引用的代码拆散。

### 3.4 `score` — 分值

数字，单位分。注意**同一节内分值可能不同**，不要按下标推算：

- 2019 第二节判断题有 1 分、1.5 分、2 分三种，选择题有 3 分、4 分两种。
- 卷面未标注的题，按该节的默认分值（判断题 1.5 分、选择题 4 分）确定。

## 4. 内容标签（`tags`）

写在题块注释的 `tags:` 里，逗号分隔，无空格。两个命名空间，各自独立受控词表。

```markdown
<!-- ... | tags: feat:code,feat:lineref,topic:graph -->
```

### 4.1 `feat:` — 内容特征

描述题干里"有什么"，**机械可判**，大部分能由脚本从正文自动推导。

<!-- VOCAB:BEGIN -->
| 标签 | 中文名 | 含义 | 判定条件 |
|---|---|---|---|
| `feat:figure` | 配图 | 题干含插图 | 题干有 `![...](assets/...)` |
| `feat:lineref` | 行号引用 | 引用代码行号 | 题干出现「第 N 行」 |
| `feat:circnum` | 填空位 | 含带圈填空位 | 题干含 `①②③④⑤` |
| `feat:formula` | 公式 | 含数学公式 | 题干含 `$...$` |
| `feat:table` | 表格 | 题干含表格 | 题干有 Markdown 表格 |
<!-- VOCAB:END -->

> 刻意**不设** `feat:code`。一题是否需要读代码，`section` 与 `group` 已经说清楚了
> （第二节、第三节的题必然依赖代码），再标一遍是冗余。这五个标签都描述
> **容易被工具弄坏的东西**：图会丢、行号会错、`①` 会被替换成 `(1)`、公式会被
> 渲染坏。它们的作用是让校验脚本能把这些题单独捞出来重点核对。

**用途**：`feat:figure` 捞出带图题做图文对齐检查；`feat:circnum` 捞出完善程序题，
核对 `①`–`⑤` 是否齐全；`feat:lineref` 捞出所有引用行号的题，确认代码行号没错位；
迁移到不支持图片的终端时避开 `feat:figure` 的题。

### 4.2 `topic:` — 知识主题

描述"考什么"，需要人工判断，一词表可扩展。一题可挂多个。

<!-- VOCAB:BEGIN -->
| 标签 | 中文名 | 典型题 |
|---|---|---|
| `topic:basics` | 计算机基础与常识 | 文件格式、编译器功能 |
| `topic:lang` | 语言基础与语法 | 类型转换、运算符优先级 |
| `topic:math` | 初等数学与代数 | 数列、方程、不等式、几何 |
| `topic:prob` | 概率与期望 | 概率计算、期望值、条件概率 |
| `topic:combinatorics` | 组合计数 | 排列、组合、容斥、鸽巢、二项式、卡特兰数 |
| `topic:number` | 进制与数论 | 二进制运算、取模 |
| `topic:bit` | 位运算 | 位压缩、异或 |
| `topic:ds` | 数据结构 | 并查集、栈、队列、哈希 |
| `topic:tree` | 树与二叉树 | 遍历、高度、笛卡尔树 |
| `topic:graph` | 图论 | 最短路、连通性、存图 |
| `topic:string` | 字符串 | 子序列、模式匹配 |
| `topic:sort` | 排序 | 稳定性、比较次数 |
| `topic:dp` | 动态规划 | 状态设计、转移方程 |
| `topic:greedy` | 贪心 | 贪心算法识别与证明 |
| `topic:search` | 搜索与回溯 | DFS、剪枝 |
| `topic:bisect` | 二分查找与二分答案 | 有序数组二分、答案单调性二分 |
| `topic:divide` | 分治 | 归并、划分与合并、分治思想 |
| `topic:sim` | 模拟与枚举 | 按规则逐步模拟 |
| `topic:complexity` | 复杂度分析 | 时间/空间复杂度 |
<!-- VOCAB:END -->

新主题一律加 `topic:` 前缀进本表，**不得**在 `tags` 里写裸词或中文。

#### 细分与父子关系

标签**只挂最具体的那一个**，不重复挂上位标签。例如排列组合题只标
`topic:combinatorics`，不再同时标 `topic:math`——否则一道题被统计两次，
题量与分值都会虚高。

| 上位标签 | 已拆出的下位标签 |
|---|---|
| `topic:math` | `topic:combinatorics`（组合计数）、`topic:number`（数论） |

筛选上位概念时，在页面上**同时选中下位标签**即可（浏览页的知识点筛选支持多选）。

考纲把「排列、组合、容斥、二项式、鸽巢、卡特兰数」归在 2.2.5 的
「离散与组合数学」之下，`topic:combinatorics` 与之一一对应。

#### 与官方考纲的对应

本词表刻意贴近 [《NOI 大纲（2025 年修订版）》](资料/NOI大纲-2025-考点.md) 的分类，
后者是 CCF 官方文件，也是 CSP-S（提高级）命题范围的权威依据：

| `topic:` | 考纲对应条目（提高级） |
|---|---|
| `topic:basics` | 2.2.1 基础知识与编程环境 |
| `topic:lang` | 2.2.2 C++ 程序设计 |
| `topic:ds` | 2.2.3 数据结构 → 线性结构、哈希表 |
| `topic:tree` | 2.2.3 数据结构 → 集合与森林、特殊树 |
| `topic:graph` | 2.2.3 数据结构 → 常见图 |
| `topic:complexity` | 2.2.4 算法 → 复杂度分析 |
| `topic:greedy` | 2.2.4 算法 → 基础算法（贪心） |
| `topic:sort` | 2.2.4 算法 → 排序算法 |
| `topic:string` | 2.2.4 算法 → 字符串算法 |
| `topic:search` | 2.2.4 算法 → 搜索算法 |
| `topic:dp` | 2.2.4 算法 → 动态规划 |
| `topic:math` | 2.2.5 数学与其他 → 初等数学、线性代数 |
| `topic:prob` | 2.2.5 数学与其他 → 概率论 |
| `topic:combinatorics` | 2.2.5 数学与其他 → 离散与组合数学 |
| `topic:bisect` | 2.2.4 算法 → 基础算法（二分法） |
| `topic:divide` | 2.2.4 算法 → 基础算法（分治算法） |
| `topic:number` | 2.2.5 数学与其他 → 初等数论 |
| `topic:bit` | 2.1.2 C++ 程序设计 → 基本运算（位运算） |

考纲还标了**难度系数【1】~【10】**（入门级 1~5、提高级 5~8、NOI 级 7~10）。若日后
需要按难度筛题，可在 `meta.json` 的题目对象上增补 `difficulty` 字段，取值直接引用
考纲对应知识点的系数——不要另起一套难度标准。

## 5. 两种载体中的写法

### `paper.md` — 题块注释

```markdown
<!-- qid: <qid> | type: <type> | score: <score> | [images: a.png,b.png] | [tags: t1,t2] -->
```

- `qid`、`type`、`score` 必填且顺序固定，` | ` 分隔。
- `images`、`tags` 选填，为空时整段省略（不写 `images:` 后留空）。
- 注释紧跟在 `### 第 N 题` 标题之后，空一行，再写题干。
- 全部标签都是 ASCII：`feat:` / `topic:` 用冒号，多个标签用逗号，**逗号后不加空格**。

### `meta.json` — 结构化字段

```json
{
  "qid": "csp-s1-2019b-030",
  "no": 30,
  "original_no": "3)",
  "section": "part2",
  "group": "阅读程序(3)",
  "type": "true_false",
  "score": 2,
  "images": [],
  "tags": ["feat:code", "feat:lineref", "feat:formula", "topic:string"],
  "answer": null
}
```

`meta.json` 是校验基准：`paper.md` 注释里的每个字段都要和它逐一对上，
不一致即报错。

### ★ 「题解」不是标签

题目正文末尾有 `<blockquote>` 题解块（`> **题解**` / `答案：` / `解释：` / `争议：`，见
[SPEC.md](SPEC.md) 3.9），大题组的代码块之后另有组级 `> **程序说明**`；用户口语里
也叫「题解标签」——但它们**都不是本词表里的条目**，**不要**往这里登记
`feat:solution` 之类的词，也不要往题块注释的 `tags:` 里加东西。

理由：它们是题块内部的一个**区块**，不是题目的分类维度；且全库 600 题里 514 题都有，
区分度太低，不值得建标签。题解的内容由 `meta.json` 的 `answer` / `answer_note` /
`dispute_note` 派生，程序说明由顶层 `groups[].program_note` 派生，都与 `tags:` 无关。

## 6. 已确认的题型分布

截至 2026-09-17 实际核对过的：

| 年份 | 试卷 | 总题数 | 第一节 | 第二节 | 第三节 |
|---|---|---|---|---|---|
| 2019 B | `csp-s1-2019b` | 43 | 单选 15 | 阅读程序 3 组，18 题 | 完善程序 2 组，10 题 |
| 2021 | `csp-s1-2021` | 43 | 单选 15 | 阅读程序 3 组，18 题 | 完善程序 2 组，10 题 |
| 2023 | 待转 | 43 | 单选 15 | 18 题 | 10 题 |
| 2024 | 待转 | 42 | 单选 15 | 17 题 | 10 题 |

2020、2022、2025 尚未核对，2025 的 PDF 文本层是广告水印，需按扫描件处理
（见 [README.md](README.md)）。

各节分值上限稳定：30 + 40 + 30 = 100。

## 7. 统一化操作示例

按 `qid` 判分（答案在 `meta.json`）：

```
questions[?qid=='csp-s1-2019b-030'].answer
```

捞出某年所有判断题：

```
questions[?type=='true_false']
```

整组抽取阅读程序第 3 组的全部小题（连同它引用的那段代码）：

```
questions[?group=='阅读程序(3)']
```

按知识点组一套图论专项练习：

```
questions[?contains(tags, 'topic:graph')]
```

统计各节分值，核对是否等于总分：

```
sum(questions[?section=='part2'].score)   →  40
```

挑出所有带图的题，检查图文是否对齐：

```
questions[?contains(tags, 'feat:figure')]
```

## 8. 词表维护

- `feat:` 词表相对封闭，出现新特征时再加（如 `feat:audio`）。
- `topic:` 词表随题库增长——遇到现有词覆盖不了的知识点，在此表登记新词后再用。
- 新增标签必须同步更新本文件，否则 `validate.py` 会拒绝。
- 改动标签属于**破坏性变更**，需在 SPEC 的版本表中记一笔，并对全库重跑校验。
