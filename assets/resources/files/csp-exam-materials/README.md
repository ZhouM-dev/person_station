# CSP 第一轮试题库

把历年 CCF CSP 第一轮认证试题整理成**机器可读的标准化格式**，便于大语言模型直接
理解题目、定位插图、按题号检索，无需回读原始 PDF。

- 格式约定见 **[SPEC.md](SPEC.md)**（文件长什么样）——唯一权威。
- 题型与标签见 **[TAGS.md](TAGS.md)**（每道题怎么被标识）。

## 组别

题库按 **组别 / 年份** 两层组织，组别目录名取 `meta.json` 的 `exam` 小写形式：

| 目录 | `exam` | 对应考纲级别 | 难度系数 |
|---|---|---|---|
| `csp-s1` | `CSP-S1` | [提高级](资料/NOI大纲-2025-考点.md) | 5~8 |
| `csp-j1` | `CSP-J1` | [入门级](资料/NOI大纲-2025-考点.md) | 1~5 |

`paper_id` 由组别、年份、卷别拼成：`csp-s1-2019b`。目录路径与 `meta.json`
必须自洽（组别名 = `exam` 小写，年份目录名 = `year`），`validate.py` 会强制检查。

> 两个组别共用同一套 `topic:` 词表——考纲里「高级别自动包含低级别知识点」，
> 所以入门级的考点是提高级的子集，不需要为 J 组另建一套标签。

## 收录状态

`题库/index.json` 当前收录 2019–2026 年 CSP-S1 与 CSP-J1 各 8 份试卷，
每组 343 题，共 16 份、686 题。每份试卷都有 `paper.md`、`meta.json`
和源 PDF 副本；各年份的来源及答案说明以对应 `meta.json` 为准。
全库已通过 `python tools/validate.py 题库` 校验。

### ⚠️ 2025 年的坑

`2025-试题.pdf` 有文本层，但**文本层内容全是「自主选拔在线」的广告水印**（18 页推广
页），真正的试卷是底层的扫描图像。直接用 PDF 转文本会得到一堆广告、且**丢失全部
题目**。

处理它必须走扫描件流程（渲染成图后识读），不能信文本层。同理，任何一份 PDF 在
转换前都应先确认文本层内容确实是题目本身，而不只是水印或页眉页脚。

### 答案编号的旁证

`2023-答案.pdf` 与 `2024-答案.pdf` 的答案序列都是**全卷连续编号**（2023 共 43 题，
2024 共 42 题），与 SPEC 中 `qid` 采用的连续编号方案一致。这也说明连续编号是这份
考试的通行做法，各年之间可以稳定对齐。

## 工具

| 脚本 | 用途 |
|---|---|
| `tools/render_pages.py` | 把 PDF 逐页渲染成 PNG（扫描件识读的第一步） |
| `tools/crop_region.py` | 从页面图裁切插图，支持遮罩掉窜入的杂字 |
| `tools/validate.py` | 校验一份试卷是否符合 SPEC（含标签词表校验） |
| `tools/tag_questions.py` | 自动推导 `feat:` 标签，并同步 `paper.md` 与 `meta.json` |
| `tools/gen_tags.py` | 从 `TAGS.md` 生成标签词表，同步到 `tags.json` 与页面 |
| `tools/survey_sources.py` | 勘察源 PDF：页数、有无文本层、文本层是否可信 |
| `tools/test_viewer.js` | 用真实 `paper.md` 测试 `viewer.html` 的解析逻辑 |
| `tools/test_page.py` | 用真实 Chrome 跑 `viewer.html` 的交互集成测试 |

三个脚本都用 `uv` 运行，依赖自动拉取，无需预装：

```powershell
# 渲染扫描件（200 dpi，输出到 _pages/）
uv run --with pymupdf python tools/render_pages.py 题目/2019-试题.pdf 题库/csp-s1/2019/_pages --dpi 200

# 裁切插图：先框大一点试裁，看图后微调；窜入的残字用 --mask 涂白
uv run --with pillow python tools/crop_region.py `
    题库/csp-s1/2019/_pages/p002.png 题库/csp-s1/2019/assets/q015-fig1.png `
    --box 615,1838,1025,2125 --mask 0,0,95,60 --trim --pad 12

# 校验（单份或整个题库）
uv run python tools/validate.py 题库/csp-s1/2019
uv run python tools/validate.py 题库
```

`validate.py` 会检查：题号连续性、题块注释与 `meta.json` 是否一致、分节分值是否等于
总分、图片引用是否存在、有无孤儿图、图片替代文本是否合规、代码块行号是否连续且格式
统一、标签是否在受控词表内、年份目录内的源 PDF 副本摘要是否与原件一致。
全部通过才算转换完成。

每个年份目录都带一份源 PDF 的逐字节副本，这样把 `题库/csp-s1/2019/` 单独拷给别人，
对方不看 `题目/` 也能核校转写是否准确。副本摘要记录在 `meta.json` 的 `source.sha256`。

## 浏览页面

将整个目录部署到静态站点后，通过 HTTP(S) 打开 `viewer.html` 即可。页面会自动读取
`题库/index.json`，再加载索引中的各份 `paper.md` 与 `meta.json`；图片和 PDF 仅在显示时
按需请求，不会在启动时下载整套资料。

本地维护时仍可双击 `viewer.html`。由于 `file://` 下不能直接 `fetch()` 同目录文件，页面会
自动切换到本地导入模式。

### 怎么读到本地文件

本地导入模式使用 **File System Access API**：

1. 首次点「选择文件夹」，浏览器弹出授权窗口，选到 `试题` 或 `题库` 目录
2. 授权后页面自动递归扫描、自动整理题目
3. 此后改了 `paper.md`，点顶栏「重新扫描」即可刷新，**不会再弹窗**

页面会尽力做到免点击：目录句柄存在 IndexedDB 里，下次打开若浏览器仍记得授权，
就直接自动载入，一次点击都不用。

**但这一步不一定成功，原因有两个，都不是页面能绕过的：**

- 浏览器规定**目录授权必须由用户点击触发**。若授权未被记住，就只能退化成一次点击
  （按钮会变成「恢复访问」）。
- `file://` 来源能否持久化存储，各浏览器策略不同。Chrome 下有可能存不住。

最坏情况也只是「每次打开点一次授权」，之后同一会话内可以无限次重新扫描。

### 浏览器支持

| 浏览器 | HTTP(S) 在线题库 | `file://` 本地目录授权 | 兜底 |
|---|---|---|---|
| Chrome / Edge | ✅ 自动加载 | ✅ 完整支持 | — |
| Firefox / Safari | ✅ 自动加载 | ❌ 不支持该 API | 文件选择或拖拽 |

本地模式下，不支持目录授权的浏览器会自动隐藏授权按钮并给出提示，功能不受影响，只是每次要手动选。

### 两个标签页

- **题目浏览**：按组别、试卷、题型、知识点、特征标签筛选，支持全文搜索。
  数据以各份 `paper.md` 为准，`meta.json` 只用来取标题、年份和组别。
- **对比查看**：左 Markdown 转写、右原始 PDF，并排校阅；也可切换成只看其一。
  右侧用浏览器内置 PDF 阅读器加载年份目录里的那份 PDF 副本。

- **公式渲染**：`$...$` 由页面内置的转换器渲染成 Unicode 记号（`\le` → ≤、
  `\log` → log、上下标、根式、分式等），不依赖 KaTeX，离线可用。
  认不出的 LaTeX 命令会退化成去掉反斜杠的原文，不会变成乱码或空白。

扫描时会跳过 `_pages/`、`_tiles/` 等以下划线开头的中间产物目录。

## 改界面

`viewer.html` 里每块可见区域都带一个 `data-ui` 标识，对照表见 **[UI-MAP.md](UI-MAP.md)**。
想改哪里，先查标识，再在文件里搜这个字符串，直接定位。

常见的显隐需求**不用改模板**，改脚本顶部的 `UI` 配置即可：

```js
const UI = {
  showTopicTags:  true,    // 题目卡片上的考点标签（知识点）
  showFeatTags:   true,    // 内容特征标签
  showGroupBadge: true,    // 大题组徽章
  showQid:        true,    // 卡片右侧 qid
  showSolution:   true,    // 题目卡片上的题解区（见 SPEC.md 3.9）
};
```

改成 `false` 只是 `display:none` 收起来，**元素仍在 DOM 里**——数据、筛选、搜索
一概不受影响。

改完跑两个测试：

```powershell
bun tools/test_viewer.js                        # 解析逻辑 + 标识契约（快）
uv run --with playwright python tools/test_page.py   # 浏览器交互（慢，但能抓到布局问题）
```

第一个检查页面标识与 UI-MAP.md 是否一一对应；第二个用系统 Chrome 打开页面，
验证滚动、折叠、字号缩放、题面浮层这些**只在浏览器里才暴露**的问题——
比如滚动锚定导致的抖动、`zoom` 被嵌套叠加。

加 `--shots` 会把关键状态截图到 `_shots/`，方便直接看效果。

## 加标签

**`TAGS.md` 是标签的唯一权威来源。** 加一个标签只需改它里面 `VOCAB` 标记之间的
表格，然后：

```powershell
uv run python tools/gen_tags.py
```

`tags.json`（校验器读的词表）和 `viewer.html`（页面显示的中文名）会一起更新。

这样设计是为了避免「规范改了、校验器没改、页面还显示英文」的三边不同步。
`validate.py` 每次都会比对这三者，任何一处落后都会报错并返回非零退出码：

```
✗ 标签词表: tags.json 与 TAGS.md 不同步
✗ 标签词表: viewer.html 的标签中文名与 TAGS.md 不同步
```

## 转换流程

1. **先判类型**：用 `to_markdown` 试转，看文本层是不是真题目。是 → 文本流程；
   否 → 扫描件流程。
2. **文本流程**：转换器出的稿**必须逐页对照原 PDF 校对**。它会把表格、代码、
   上下标弄乱（例如 2021 年的程序代码被转成了表格，缩进全丢）。
3. **扫描件流程**：渲染成图 → 逐页识读转写 → 裁切插图 → **回看图确认没切掉笔画**。
4. **补齐元数据**：写 `meta.json`，把分值与 `sections` 对上。
5. **校验**：`uv run python tools/validate.py 题库/<年份>`，必须零错误。
6. **清理**：删掉 `_pages/` 中间产物（可随时重新生成）。
7. **登记**：把新试卷加进 `题库/index.json`。
