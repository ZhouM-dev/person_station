# 试题库格式规范 v1.5

> 首行的 `vX.Y` 是给 `tools/gen_index.py` 读的**机器标记**——它会被写进
> `题库/index.json` 的 `spec_version`。提升它时必须同时跑一次
> `uv run python tools/gen_index.py` 重建索引，否则 `gen_index.py --check` 会红。
> 内容以 §7 的版本表为准。

本规范定义 `题库/` 下所有标准化试卷的统一格式。目的是让机器（尤其是大语言模型）
在**不依赖原始 PDF**的情况下，准确理解题目、定位插图、引用题号。

所有规范化产物必须满足本规范。转换后用 `tools/validate.py` 校验。

---

## 1. 目录结构

```
试题/
├── SPEC.md                  # 本规范
├── README.md                # 项目说明
├── 题目/                    # 原始 PDF，只读，不改名、不移动
├── 题库/                    # 标准化产物
│   ├── index.json           # 全库总索引
│   └── <组别>/              # 例：csp-s1/
│       └── <年份>/          # 例：2019/
│           ├── <年份>-试题.pdf  # 原始 PDF 的副本，见 1.1
│           ├── paper.md     # 试卷正文（题目 + 题解 + 组级程序说明，见 3.9）
│           ├── answers.md   # 【不使用】答案与解析写在 paper.md 的题解块里，见 3.9
│           ├── meta.json    # 结构化元数据（答案、解释、争议、组级程序说明）+ 题目索引
│           └── assets/      # 插图
└── tools/                   # 转换与校验脚本
    ├── render_pages.py
    ├── crop_region.py
    ├── tag_questions.py     # 把 meta.json 同步到 paper.md（题块注释 + 题解 + 程序说明）
    ├── lint_notes.py        # 题解文字的写作规范自检（长度、句末标点、禁用词）
    └── validate.py
```

**路径规则：`题库/<组别>/<年份>/`**

组别目录名取 `exam` 字段的小写形式：

| 组别目录 | `exam` | 含义 |
|---|---|---|
| `csp-s1` | `CSP-S1` | CCF CSP 提高级（Senior）第一轮 |
| `csp-j1` | `CSP-J1` | CCF CSP 入门级（Junior）第一轮 |

**一份试卷一个目录**。目录路径必须与 `meta.json` 自洽，由校验器强制：

- 第 1 段 = `exam` 的小写形式
- 第 2 段 = `year`，四位数字

`paper_id` 再由两者加卷别拼成：

```
paper_id = {exam 小写}-{year}{卷别小写}
```

例：`题库/csp-s1/2019/` → `paper_id: csp-s1-2019b`（该卷为 B 卷）。

> **卷别不进目录名**，只记在 `meta.json` 的 `paper_variant`。唯一例外：同一组别、
> 同一年真的存在多卷时，该年下**所有**卷一律带卷别后缀（`2019-a/`、`2019-b/`），
> 不允许"有的带有的不带"。届时目录改名后需重跑校验。

### 1.1 源 PDF 副本

每个年份目录内保留一份原始 PDF 的**逐字节副本**，沿用原文件名。

- `题目/` 仍是源文件的权威位置；年份目录内的副本只为让该目录**自包含**——
  把 `题库/csp-s1/2019/` 单独拷给别人，对方不看 `题目/` 也能核校转写是否准确。
- 副本一经放置不得修改。`meta.json` 的 `source.sha256` 记录其摘要，
  校验脚本可据此确认副本未被篡改、且与 `题目/` 中的原件一致。

## 2. 命名与标识

### 2.1 试卷 ID（`paper_id`）

格式：`{考试}-{年份}{卷别}`

| 考试 | 含义 |
|---|---|
| `csp-s1` | CCF CSP 提高级（Senior）第一轮 |
| `csp-j1` | CCF CSP 入门级（Junior）第一轮 |

示例：`csp-s1-2019b`（2019 年提高级第一轮 B 卷）

卷别无标注时省略字母：`csp-s1-2021`。

### 2.2 题目 ID（`qid`）

格式：`{paper_id}-{序号}`，序号为**全卷连续编号**，3 位补零。

示例：`csp-s1-2019b-015`

**连续编号规则**（关键）：不沿用原卷的分节编号。按试卷物理顺序，给每一道**可计分的
小题**依次编号，从 `001` 开始，跨节不重置。

以 CSP-S 2019 B 卷为例：

| 节 | 原卷编号 | 全卷序号 |
|---|---|---|
| 一、单项选择题 | 1 ~ 15 | 001 ~ 015 |
| 二、阅读程序 (1) 判断题 | 1) ~ 4) | 016 ~ 019 |
| 二、阅读程序 (1) 选择题 | 5) ~ 6) | 020 ~ 021 |
| 二、阅读程序 (2) | 1) ~ 6) | 022 ~ 027 |
| 二、阅读程序 (3) | 1) ~ 6) | 028 ~ 033 |
| 三、完善程序 (1) | 1) ~ 5) | 034 ~ 038 |
| 三、完善程序 (2) | 1) ~ 5) | 039 ~ 043 |

> 这样做是因为历年原卷编号方式不统一（有的年份分节内重置，有的年份全卷连续），
> 统一成连续编号后，跨年份检索、组卷、比对才有稳定的主键。

原卷编号一律保留在 `meta.json` 的 `original_no` 字段，用于回溯。

> 旁证：官方发布的答案文件本身就用全卷连续编号（2023 答案 43 题、2024 答案 42 题，
> 均从 1 排到尾）。采用连续编号可以直接和答案序列逐位对齐，不必做分节换算。

### 2.3 图片命名

格式：`q{题号3位}-fig{序号}.png`，题号用**全卷连续序号**。

示例：`q015-fig1.png`、`q015-fig2.png`

- 一题多图时序号递增；小题配图也归到其所属大题号（如第 15 题的图即 `q015-fig1.png`）。
- 只允许 PNG。扫描件按原分辨率裁切，**不放大、不锐化**。
- 文件名一经确定不得更改，`paper.md` 与 `meta.json` 同时引用它。

## 3. `paper.md` 书写规范

### 3.0 标题层级

四个层级各司其职，**不得混用**：

| 层级 | 用途 | 例子 |
|---|---|---|
| `##` | 节 | `## 二、阅读程序` |
| `###` | 大题组；或第一节的题目 | `### (1)`；`### 第 1 题` |
| `####` | 组内分栏 | `#### 判断题`、`#### 选择题` |
| `#####` | 题目（第二、三节） | `##### 第 16 题` |

规则：

- **第一节**没有大题组，题目直接用 `###`：`### 第 1 题`
- **第二、三节**先有 `###` 大题组，再有 `####` 分栏，题目用 `#####`
- `####` 分栏标题**只允许** `判断题` / `选择题` / `单选题` 三种
- 大题组标题（`### (1)`）与该组的 `<!-- group: -->` 注释配对出现

> ⚠️ **代码块、提示、分栏标题都必须挂在某个分栏之下，不得悬空。**
>
> 这条不是形式要求。曾有解析器只识别「题目」一种结构，凡是长在题目之外的内容
> ——组内那段程序代码、`#### 选择题` 这个分栏标题——都被并进了上一道题的正文，
> 表现为代码整段消失、`#### 选择题` 被当普通文字渲染出来。
>
> 排版时请务必保证：`### (1)` 之后紧跟 `<!-- group: -->`，再是代码块，
> 最后才是第一个 `####` 或 `#####`。中间不要插入别的东西。

### 3.1 整体骨架

```markdown
---
paper_id: csp-s1-2019b
title: CCF 非专业级别软件能力认证第一轮（CSP-S）提高级 C++语言试题 B卷
year: 2019
date: 2019-10-19
total_score: 100
---

# CCF 非专业级别软件能力认证第一轮（CSP-S）提高级 C++语言试题 B卷

认证时间：2019 年 10 月 19 日 09:30~11:30

考生注意事项：
- 试题纸共有 10 页，答题纸共有 1 页，满分 100 分。请在答题纸上作答，写在试题纸上的一律无效。
- 不得使用任何电子设备（如计算器、手机、电子词典等）或查阅任何书籍资料。

## 一、单项选择题

> 共 15 题，每题 2 分，共计 30 分；每题有且仅有一个正确选项。

### 第 1 题

<!-- qid: csp-s1-2019b-001 | type: single_choice | score: 2 -->

题干……

- A. 选项
- B. 选项
- C. 选项
- D. 选项

（后续题目……）
```

- 文件顶部必须有 YAML front matter，字段见 3.2。
- 节标题用 `##`，与试卷原文一致（`一、单项选择题` 等）。
- 每题用 `### 第 N 题`，N 为**全卷连续序号**。
- 节下的分值说明用引用块 `>` 原样保留。

### 3.2 YAML front matter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `paper_id` | 是 | 见 2.1 |
| `title` | 是 | 试卷全称 |
| `year` | 是 | 整数 |
| `date` | 否 | 认证日期 `YYYY-MM-DD`，未知填 `null` |
| `total_score` | 是 | 满分 |

### 3.3 题目块

每题以一行 HTML 注释开头，承载机器可读的题目标识：

```markdown
<!-- qid: csp-s1-2019b-001 | type: single_choice | score: 2 | answer: C | tags: topic:lang -->
```

字段顺序固定，以 ` | ` 分隔：

| 顺序 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 1 | `qid` | 是 | 见 2.2 |
| 2 | `type` | 是 | `single_choice`（单选）/ `true_false`（判断） |
| 3 | `score` | 是 | 数字，单位分 |
| 4 | `answer` | 否 | 单选填 `A`~`D`；判断填 `T`（正确）/ `F`（错误） |
| 5 | `images` | 否 | 图片文件名，多张逗号分隔 |
| 6 | `tags` | 否 | 内容标签，逗号分隔、逗号后不加空格，词表见 [TAGS.md](TAGS.md) |

- 选填字段为空时**整段省略**（不写 `answer:` 后留空）。
- 注释之后空一行，再写题干。
- `answer` 与 `meta.json` 的 `questions[].answer` 必须一致，由校验器强制。
  两处都写是为了让 `paper.md` 自包含——单独把它交给别的 AI，不配 `meta.json`
  也能判分。

### 3.4 题干与选项

- 题干保持原文措辞，**不得改写、精简或补充**。原文的错别字也照录。
- 选项统一写成 Markdown 无序列表，每项一行：`- A. 内容`。
  - 原卷选项同行排列（`A. 甲  B. 乙`）时，一律拆成四行。
- 判断题选项不写，题干末尾保留原文的 `（ ）`。
- 原文空格、全角括号 `（）` 保留。
- **中文与西文之间的空格**：中文（含全角标点）与半角 ASCII 字母/数字相邻处，
  补一个半角空格（`在 Linux 系统中`，不是 `在Linux 系统中`）。
  依据是**渲染所见**，不是文本层字符流——文本层的中西文自动间距是排版属性，
  不写进字符流，照抄会得到单侧空格的怪写法。
  例外：代码块内、行内代码内、`$…$` 公式内、图片路径内，一律不动。

### 3.5 数学与代码

- **行内公式**用 `$...$`。例：`第 $n$ 行的数为 $a_{n,1}, a_{n,2}, \ldots, a_{n,n}$`。
- **行间公式**用 `$$...$$`，单独成段。
- **代码**用围栏代码块，语言标注 `cpp`。
- **行内代码片段**用反引号。原卷用中文引号包裹代码片段时（如 `"<"`、`"fa[i] = 0;"`），
  一律改为反引号，不再保留引号——引号是排版手段，不是题目内容。
- 原卷对**代码标识符**的加粗强调（如 **a[i]**、**status**、**ull**），改为行内代码或普通文本。
- 原卷对**正文的加粗强调**（如「**不能**用贪心法」「该图**至多**有」），一律保留为 `**…**`。
  加粗的词往往是「不能」「至多」这类**决定题意**的成分，丢弃会改变语义。
- **西文与数字的整体加粗一律不保留**（见下方「字体约定 vs 语义强调」）。
- 区分标准看**加粗的是什么**，不看加粗的样式：
  代码标识符 → 行内代码；分值、题号、`√ ×` 等排版性加粗 → 不保留；其余正文强调 → 保留。

> 这三条是**排版归一化**，不属于改写：引号换反引号、加粗换代码体，都不改变任何
> 字符的内容。除此之外的措辞一律照录，包括原文的错别字。

#### 字体约定 vs 语义强调（★ 判加粗前必读）

「加粗」在卷面上有两种来源，**只有第二种才记 `**…**`**：

| 来源 | 表现 | 处理 |
|---|---|---|
| **字体约定** | 全卷的西文与数字统一用粗体字面（与中文正文混排时看着「更黑」） | ❌ **不记录** |
| **语义强调** | 个别**中文词**被挑出来加粗，同页其余中文不加粗 | ✅ 记为 `**…**` |

**判别捷径**：去看**页脚页眉**。页脚的「第 N 页，共 M 页」永远不会承载语义强调——
若它的数字是粗的，那这一卷的「西文/数字加粗」就是字体约定，全卷一律不记录。

> **CSP-S 2020 就是典型**：页脚「第1页，共13页」的 `1`/`13`、节标题「共 15 题，每题 2 分」
> 的 `15`/`2`、第 3 题题干里的 `8`/`24`/`2048×1024`/`32` 全是粗体，连选项 `30G`/`90G` 也是。
> 页脚那处证明了这是**字体约定**，所以这些数字**都不记 `**…**`**；
> 该卷只记 25 处中文强调（`不能`、`至多`、`必须`、`单调递增`…）。

> ⚠️ **判加粗不能靠「看着更黑」，必须量化。** 汉字字形本身差异很大
> （如「大」的撇捺在宋体里天然就粗），目视极易误判。
> 可行做法：在同一张高 dpi 图上量**笔画宽**（连通域 `2×面积/周长`），
> 或用「同字自比」（同一个字在不同位置的着墨率）——真加粗会抬升 **35% 以上**。
>
> **本库已有两次教训**：2026-09-18 一次目视复核把 2019 的 2 处「一定」误判为加粗
> （实测与同页另一处「一定」逐像素同粗，面积差 <1.5%），后被 400 dpi 量化复核推翻；
> 同一次复核又漏掉了 2020 的真加粗。「看着像」不是证据。

### 3.6 代码行号（重要）

阅读程序、完善程序的代码**保留原卷行号**，因为题目会直接引用行号
（如"将第 21 行中 `t` 的类型声明从 `int` 改为 `double`"）。

格式：行号右对齐占 3 列，后跟 2 个空格，再是代码原文（含原有缩进）。

````markdown
```cpp
  1  #include <cstdio>
  2  using namespace std;
  3  int n;
  4  int a[100];
  5
  6  int main() {
  7      scanf("%d", &n);
```
````

- 行号必须与原卷一致（含空行，空行也要占一行号）。
- 去掉行号还原可编译代码的规则：删除每行行首的 `^\s*\d+  `。
- **宽度与原卷写法是两件事，不要混为一谈**：
  - 「3 列」是**本库统一的宽度要求**——各年原卷行号宽度不一（2 列或 3 列），
    本库一律右对齐补足到 3 列，方便机器解析。
  - 「前导零」是**原卷的排版事实**——原卷印 `01` 的写 ` 01`，原卷印 `1` 的写 `  1`。
  - **不得为凑宽度而删掉前导零，也不得为保留前导零而改变总宽。**
- 实测各年原卷写法（供核对，勿凭印象）：

  | 年份 | 原卷 1~9 的印法 |
  |---|---|
  | 2019 | `1 `（无前导零） |
  | 2020 | `01` |
  | 2021 | `09` |
  | 2022 | `9 `（无前导零） |
  | 2023 | `08` |
  | 2024 | `01` |
  | 2025 | `01` |

### 3.7 填空标记

完善程序中的待填空位沿用原卷的带圈数字：`①` `②` `③` `④` `⑤`。
在代码块与题干中保持一致，不得替换成 `(1)`、`___` 等其他写法。

### 3.8 图片引用

```markdown
![数字三角形示意图](assets/q015-fig1.png)
```

- 相对路径，相对 `paper.md` 所在目录。
- 替代文本（`![]` 内）必须是**简短中文描述**，不得直接抄文件名。
- 图片单独成段，前后各留一个空行。
- 禁止 base64 内联、禁止引用 `题库/` 之外的路径。

### 3.9 题解

每道题在**正文最末尾**（选项之后）带一个题解块，回答「答案是什么、为什么」。

```markdown
##### 第 33 题

<!-- qid: csp-s1-2022-033 | type: single_choice | score: 3 | answer: B | tags: ... -->

若 `tlen=10`，输出为 2，则 `slen` 最小为（ ）。

- A. 1
- B. 10
- C. 0
- D. 12

> **题解**
> 答案：B
> 解释：官方答案表给 D，但按卷面程序实编译运行（输入 `1000000 19`）输出 `87GIB`，对应本卷 B 项。
```

争议题在 `解释：` 之后再追加一行 `争议：`：

```markdown
> **题解**
> 答案：C
> 解释：……（为什么选它）
> 争议：……（与哪个来源冲突、对方给什么、本卷取什么、依据是什么）
```

#### 逐字规格

| 项 | 规格 |
|---|---|
| 首行 | `> **题解**` —— `> ` 一个半角空格，`题解` 两字，两侧各两个星号，**行尾无空格** |
| 第二行 | `> 答案：<值>` —— 冒号用**全角 `：`** |
| 第三行 | `> 解释：<正文>` —— **有 `answer` 的题必写** |
| 第四行起 | `> 争议：<正文>` —— **可选**，仅争议题写，且**必须排在 `解释：` 之后** |
| 前缀 | 每一行都以 `> `（半角 `>` + 一个半角空格）开头 |
| 位置 | 题目正文**最后**的内容，其后到下一个标题/注释之间只能有空行 |
| 前置空行 | 与上文之间**恰好一个空行** |
| 多行 | 允许换行，**续行也以 `> ` 开头**，但**不重复** `解释：` / `争议：` 前缀 |
| 围栏 | **不得**出现围栏代码块 ` ``` ` —— 展示输出用行内代码（`` `83` ``） |

#### 答案的写法（★ 注意判断题）

| `type` | `meta.answer` | 题解里写 |
|---|---|---|
| `single_choice` | `A`~`D` | `答案：A`（原样） |
| `true_false` | `T` | `答案：√` |
| `true_false` | `F` | `答案：×` |

判断题刻意用卷面答案卡的 `√`/`×` 而不是 `T`/`F`：学员一眼就懂；机器读的是题块注释里
的 `answer: T/F`，两者由校验器强制对应。

#### 什么题不写题解

**`meta.answer` 为 `null` 的题，整个题解块不写**（无答案源，不得编造），
`answer_note` / `dispute_note` 也都不写。有答案的题**都写**，而且是**每题都写 `解释：`**
（v1.5 起，不再区分「有没有争议」）。

#### 怎么写

- `解释：` 面向**学员**：让他读完能自己复算、或复述为什么其它候选不成立。
  长度一般 1~4 句（程序题可更长），上限 800 字。**必写要素**是「得出答案的关键一步」
  ——算式、判据、代码行为，或实跑的关键输入与输出。
- `争议：` 只在「与来源冲突 / 题面与答案不自洽 / 答案不唯一」时写。要写清**与哪个来源
  冲突、对方给什么、本卷取什么、依据是什么**，不得只写「有争议」而不给依据。
- 写作规范与题型范式见 [协作/手册/11-题解写作.md](协作/手册/11-题解写作.md)，
  机器自检用 `uv run python tools/lint_notes.py 题库/<组别>/<年份>`。

#### ★ 题解由 `meta.json` 派生，禁止手工编辑

题解块是 `meta.json` 的镜像，不是手写内容：

- `答案：` 由 `questions[].answer` 派生（判断题按 `T→√`、`F→×` 映射）；
- `解释：` 由 `questions[].answer_note` 派生（**有答案的题该字段必填**）；
- `争议：` 由 `questions[].dispute_note` 派生（无争议的题不写该字段）。

**禁止在 `paper.md` 里手改题解块**——一旦答案变了就两处对不上。正确做法是改
`meta.json` 后重跑同步：

```
uv run python tools/tag_questions.py 题库/<组别>/<年份>
uv run python tools/tag_questions.py 题库 --check     # 只检查，不一致就报错
```

> **铁律**：任何题的 `answer` / `answer_note` / `dispute_note` 被改动后，**必须重跑
> `tag_questions.py` 该卷**，题解块会自动跟上。核验改判答案时同样适用。

> 「题解」**不是** `tags:` 词表里的条目，不要往题块注释的 `tags:` 里加东西，
> 见 [TAGS.md](TAGS.md) §5。

#### ★ 组级「程序说明」（v1.5 新增）

「这段代码整体在求解什么」属于**大题组**，不属于任何小题——所以它既不写在题解块里，
也不在题块注释里，而是单独一块，放在该组的 material 区：

```markdown
### (1)

<!-- group: 阅读程序(1) -->

```cpp
  1  #include <cstdio>
  ……（程序代码）
```

> **程序说明**
> 这段程序读入一个字符串，按下标是否为串长的约数把小写字母改成大写……

#### 判断题          ← 程序说明必须在第一个分栏之前

##### 第 16 题
```

| 项 | 规格 |
|---|---|
| 位置 | 该组**代码块之后、本组第一个 `####` / `#####` 之前**（见 3.0 的悬空内容规则） |
| 首行 | `> **程序说明**`，其后每行以 `> ` 开头，续行不重复前缀 |
| 内容 | 这段代码在求解什么问题、输入输出是什么、用了什么关键做法（二分 / 递推 / 贪心 / DP / 排序 / 位运算…），以及理解本组题要抓住的一两个要点。60~500 字，学员视角，不是逐行注释 |
| 数量 | 每个大题组**恰好一个**；没有 `program_note` 的组不得有这一块 |
| 来源 | `meta.json` 顶层 `groups[].program_note`，由 `tag_questions.py` 同步 |

**`program_note` 与答案无关**：它描述程序本身在干什么，所以哪怕某卷没有答案，
这一栏照样能写、也该写。

```json
{
  "paper_id": "csp-s1-2019b",
  "title": "CCF 非专业级别软件能力认证第一轮（CSP-S）提高级 C++语言试题 B卷",
  "exam": "CSP-S1",
  "year": 2019,
  "paper_variant": "B",
  "date": "2019-10-19",
  "duration_minutes": 120,
  "total_score": 100,
  "question_count": 43,
  "source": {
    "file": "题目/2019-试题.pdf",
    "copy": "题库/csp-s1/2019/2019-试题.pdf",
    "sha256": "B9D60176E01FF7F122018BF0D547B067597A50BC68F713C881A978828372B8E5",
    "pages": 10,
    "kind": "scanned",
    "ocr": true
  },
  "converted_at": "2026-09-17",
  "spec_version": "1.5",
  "sections": [
    {
      "id": "part1",
      "title": "一、单项选择题",
      "score": 30,
      "qids": ["csp-s1-2019b-001", "..."]
    }
  ],
  "groups": [
    {
      "name": "阅读程序(1)",
      "section": "part2",
      "program_note": "这段代码整体在求解什么问题、输入输出是什么、关键做法是什么，见 3.9。"
    }
  ],
  "questions": [
    {
      "qid": "csp-s1-2019b-001",
      "no": 1,
      "original_no": "1",
      "section": "part1",

      "type": "single_choice",
      "score": 2,
      "images": [],
      "tags": ["topic:lang"],
      "answer": "C",
      "answer_note": "派生到 paper.md 题解块的 `解释：` 行；有 answer 的题必填，见 4.1",
      "dispute_note": "可选：派生到 `争议：` 行，只有争议题才写"
    }
  ]
}
```

### 字段说明

| 字段 | 说明 |
|---|---|
| `source.file` | 源 PDF 相对仓库根的路径（权威位置在 `题目/`） |
| `source.copy` | 年份目录内副本的路径，见 1.1 |
| `source.sha256` | 源 PDF 的 SHA-256，十六进制大写 |
| `source.kind` | `text`（原生文本层）/ `scanned`（扫描件） |
| `source.ocr` | 是否经过 OCR / 人工识读 |
| `sections[].id` | `part1` / `part2` / `part3`，按试卷节次 |
| `groups[]` | **顶层数组**，大题组的组级说明。每项 `{name, section, program_note}`；`name` 必须与 `questions[].group` 逐字一致。第一节没有组，不出现该键或为空数组 |
| `groups[].program_note` | 「整段代码在求解什么」的说明，**必填**（有 `groups[]` 项就要非空），派生到该组 material 区的 `> **程序说明**` 块，见 3.9。**与答案无关**，无答案源也能写 |
| `questions[].no` | 全卷连续序号，与 `qid` 末三位一致 |
| `questions[].original_no` | 原卷编号，如 `"1"`、`"2)-3"`、`"①"` |
| `questions[].group` | 所属大题，如 `"阅读程序(1)"`；单选节为 `null` |
| `questions[].type` | `single_choice` / `true_false` |
| `questions[].images` | 图片文件名数组，与 `paper.md` 引用一致 |
| `questions[].tags` | 内容标签数组，受控词表见 [TAGS.md](TAGS.md) |
| `questions[].answer` | 答案。单选填 `"A"`；判断填 `"T"`/`"F"`；未知填 `null` |
| `questions[].answer_note` | **题解的解释正文**，见 4.1。有 `answer` 的题**必填**（非空字符串）；`answer` 为 `null` 的题不写该字段。多行用 `\n`；解析为 `paper.md` 题解块的 `解释：` 行，见 3.9 |
| `questions[].dispute_note` | **争议原因**，可选。只有争议题才写；解析为题解块的 `争议：` 行，且必须排在 `解释：` 之后。没有则**不写该字段**（不是写空串） |

> ⚠️ **`answer_note` 的语义在 v1.5 变更过**：v1.4 时它专指「存疑说明」，只给争议题写；
> **从 v1.5 起它是「解释正文」，有答案的题一律必填**。旧的「没有问题的题目只写答案」
> 口径已作废，见 `协作/需求/02-题解标签.md` 的 v2 附则。

### 4.1 `questions[].answer_note` / `dispute_note`（题解的文字来源）

- 字段位置：紧跟 `answer` 之后（`answer` → `answer_note` → `dispute_note`）。
- **`answer_note` 必填**（只要 `answer` 非空）；`dispute_note` 只在争议题上出现。
- 内容规范见 [协作/手册/11-题解写作.md](协作/手册/11-题解写作.md)：面向学员、
  20~800 字、句末用中文句末标点、不得含围栏代码块、不得出现内部协作用语。
  自检命令：`uv run python tools/lint_notes.py 题库/<组别>/<年份>`。
- 优先取 `协作/核验/<paper_id>.md` 里已有的实跑结论；核验报告没覆盖的题自己推导，
  **程序题要真编译真运行**，拿不准的写进 `协作/待决/<paper_id>.md`，不得编造。
- 程序输出、变量名、字符串用行内代码；`$…$` 公式可用（同步工具会先剥离题解块再推导
  `feat:` 标签，不会误加 `feat:formula`）。

## 5. 转换流程

### 5.1 原生文本 PDF（2021 及以后）

1. `mcp__cherry-tools__to_markdown` 转出草稿。
2. **逐页比对原 PDF 校对**——转换器会把表格、代码、上下标弄乱，必须人工复核。
3. 按第 3 节重排为题块格式。
4. 插图从原 PDF 提取或裁切。

### 5.2 扫描件 PDF（2019、2020）

无文本层，需识读：

1. 渲染页面：
   ```
   uv run --with pymupdf python tools/render_pages.py 题目/2019-试题.pdf 题库/csp-s1/2019/_pages --dpi 200
   ```
2. 逐页识读页面图，按第 3 节转写为 `paper.md`。
3. 定位插图，裁切：
   ```
   uv run --with pillow python tools/crop_region.py ^
       题库/csp-s1/2019/_pages/p002.png 题库/csp-s1/2019/assets/q015-fig1.png ^
       --box 615,1838,1025,2125 --mask 0,0,95,60 --trim --pad 12
   ```
   - `--box` 用原图像素坐标。先用大框试裁、看图微调。
   - 窜入的上一行残字、页码、水印用 `--mask` 涂白（坐标相对裁切框）。
4. **必须回看裁切结果**，确认没有被切掉的笔画、没有残留杂字。
5. 删除 `_pages/` 中间产物（可由第 1 步重新生成）。

### 5.3 校验

```
uv run python tools/validate.py 题库/csp-s1/2019
```

## 6. 质量校验清单

转换完成后逐项确认：

- [ ] `paper_id` 格式正确，年份、卷别无误
- [ ] 全卷题号连续无跳号，`paper.md` 与 `meta.json` 数量一致
- [ ] 每题题块注释含 `qid` / `type` / `score`，且与 `meta.json` 一致
- [ ] 各节分值之和 = `total_score`
- [ ] 所有 `![...](assets/...)` 指向的文件存在，且 `assets/` 内无未被引用的孤儿图
- [ ] 图片替代文本是中文描述，非文件名
- [ ] 标题层级符合 3.0（节 `##`、大题组 `###`、分栏 `####`、题目 `###`/`#####`）
- [ ] 代码块、提示、分栏标题都挂在分栏之下，没有悬空内容
- [ ] 代码块行号与原卷一致，空行未丢失
- [ ] 带圈数字 `①②③` 未被替换
- [ ] 题干、选项与原文逐字一致，未改写
- [ ] 有答案的题都有题解块，无答案的题都没有（3.9）；题解块是正文最后的内容
- [ ] **每题都有 `解释：`**（有答案的题 `answer_note` 必填、非空、20~800 字）
- [ ] **每个大题组都有 `> **程序说明**`**，位置在代码块之后、本组第一个分栏之前，
      内容与 `meta.groups[].program_note` 逐字一致；没有 `program_note` 的组没有该块
- [ ] 争议题在 `解释：` 之后有一行 `争议：`，写清了与来源的冲突与依据；
      非争议题没有 `争议：` 行
- [ ] 题解块与 `meta.json` 逐字对应（`答案：` 与 `answer`、`解释：` 与 `answer_note`、
      `争议：` 与 `dispute_note`），且未手改过——改过就重跑 `tools/tag_questions.py`
- [ ] `uv run python tools/lint_notes.py 题库/<组别>/<年份>` → 退出码 0
- [ ] 年份目录内的源 PDF 副本与 `题目/` 原件摘要一致
- [ ] `tools/validate.py` 全部通过
